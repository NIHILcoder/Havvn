# Создание торрентов: изменения 27 октября 2026

Первоначальные изменения сделаны по чтению кода приложения и установленной версии WebTorrent/create-torrent, с отложенными по просьбе пользователя тестами. После отдельной команды «проведи тесты» выполнены функциональные проверки и сборка; актуальные результаты находятся в [отчёте](torrent-creation-tests-20261027.md).

## Первый набор изменений

- Размер частей в предпросмотре и создателе рассчитывается одной функцией. В предпросмотре учитываются исключения, включая исключённые каталоги. При исключении всех файлов кнопки создания и предпросмотра недоступны.
- Старый ответ сканирования больше не заменяет новую выборку. Во время сканирования создание недоступно. Неполное дерево не выдаётся за полный список: выбор отдельных файлов отключается с пояснением.
- Обход дерева для интерфейса не следует символьным ссылкам; ограничение количества элементов учитывает и каталоги.
- Перетаскивание файла и старое окно создания сохраняют расширение имени.
- При сборке нескольких источников совпадающие имена корней отклоняются до хеширования. Ошибка чтения больше не превращается в молчаливое исключение файла или нулевой размер. Временные копии содержимого больше не создаются.
- Выходной путь не может совпадать с выбранным источником. Существующий выходной `.torrent` внутри исходной папки исключается из сборки новой версии.
- Прогресс хеширования берётся из `create-torrent.onProgress`, по обработанным байтам, с ограничением частоты обновления. Оценка по условной скорости 80 МиБ/с удалена.
- Создатель больше не запускает торрент-клиент: метаданные строятся потоковым чтением явного списка файлов. Пустой список трекеров сохраняется пустым; публичные трекеры автоматически не подставляются.
- Одновременно выполняется одно задание создания, включая подготовку автораздачи. Хеширование прерывается после пяти минут без прогресса, а не после пяти минут общей работы. Потоки закрываются при завершении и ошибке.
- Пакетное создание освобождает подписку на прогресс при ошибке. Уже завершённые элементы пропускаются при повторном запуске, повторное добавление того же пути не дублирует элемент.
- Старое окно создания нельзя закрыть через оболочку диалога во время работы. Хранилище страницы не сбрасывает выполняющееся задание.

## Оформление в стиле Havvn

Страница и связанные окна приведены к плоским поверхностям Ember: тонкие разделители, тематические цвета, компактные вкладки и общие переключатели. Источник и параметры разделены на две панели; в узком контейнере они идут последовательно. Нижние действия имеют отдельные отступы от разделителя и края окна. У выбранного источника виден локальный путь.

Убраны оставшиеся иконки с галочками в этом сценарии, большой круг прогресса и отдельная анимированная кнопка предпросмотра. Результат создания показывает параметры обычными строками. Стили страницы, старого диалога, предпросмотра и пакетного создания ограничены своими контейнерами, чтобы общие классы не меняли другие экраны.

`npm run typecheck:renderer` прошёл после правок. Сохранены статические снимки реальных компонентов с демонстрационными данными: [основной вид](../artifacts/torrent-creation-design-20261027/selected.png), [узкое окно](../artifacts/torrent-creation-design-20261027/narrow.png), [светлая тема](../artifacts/torrent-creation-design-20261027/light.png), [предпросмотр](../artifacts/torrent-creation-design-20261027/metadata.png). Они получены серверным рендерингом без API-моста и выполнения эффектов, затем сняты в Electron. Функциональные тесты, создание торрентов и раздача не выполнялись.

## Уточнение ширины, добавления источников и параметров

После отзыва о широком окне снято ограничение 1160 px: панели занимают доступную рабочую ширину с обычными отступами по краям. [Широкая раскладка](../artifacts/torrent-creation-design-20261027/wide.png).

Переключатель «Папка / Файлы» удалён. Одна область принимает файлы, папки и смешанный набор; повторное добавление дополняет список. Для системного выбора остаются две команды добавления. Список показывает имя, тип, путь, размер и отдельное удаление каждого источника. Повторные пути и элементы внутри уже выбранного родительского каталога не дублируются; ручное имя и исключения для сохранённых источников остаются.

Адреса проверяются с номерами ошибочных строк до создания и предпросмотра. Поддерживаются UDP, HTTP, HTTPS, WS/WSS для трекеров и HTTP/HTTPS для веб-сидов. Пустые строки разделяют группы трекеров, повторы удаляются из итоговых параметров. Этим разбором пользуются страница, старый диалог и пакетное создание; создатель также проверяет адреса. Поздний ответ загрузки публичных трекеров не заменяет пользовательский список. [Отображение ошибки адреса](../artifacts/torrent-creation-design-20261027/invalid.png).

В основной вкладке видны размер части и количество трекеров; эти значения открывают соответствующую настройку. Уточнены подсказки к приватному режиму, размеру частей и веб-сидам.

Сохранение `.torrent` и запуск раздачи теперь разделены: ответ содержит `seedingStatus` (`not-requested`, `queued`, `failed`) и отдельную ошибку раздачи. Ошибка `addSeed` больше не скрывает сохранённый файл. Страница, пакетное создание и старый диалог показывают частичный успех; статус результата не вычисляется из положения переключателя формы. Повтор запуска из результата добавлен отдельным этапом 28 октября, описанным ниже.

Полная статическая проверка типов прошла. После унификации разбора адресов в двух дополнительных диалогах повторно проверен renderer. Функциональные тесты и фактические операции перетаскивания/создания/раздачи остаются отложены. Снимки вёрстки содержат демонстрационные данные без выполнения эффектов и API-моста.

## Исправления создания и автораздачи

Подробности: [сопоставление метаданных и исходников](torrent-seeding-fixes.md).

Уточнение предыдущего вывода: обычные новые записи с `torrentFilePath` уже использовали `client.add`. Пересборка через `client.seed` оставалась в старой ветке для записей без метаданных; утверждение, что она происходила при каждом запуске, было слишком широким. Эта ветка удалена. Обе реализации теперь используют сохранённые метаданные с проверкой infoHash и отдельной копией в профиле приложения.

Исправлено сопоставление нескольких файлов/папок в классическом движке, в том числе при пользовательском имени корня. Его хранилище исходников работает только на чтение. Проверка содержимого предшествует обнаружению пиров. Нативный движок поддерживает несколько источников с общей физической структурой папок; разрозненные источники требуют классического движка. Скрытого копирования содержимого нет.

Создатель использует явный список файлов с исключениями, включает скрытые обычные файлы, пропускает ссылки, проверяет изменения источников и записывает `.torrent` через временный файл рядом с результатом. Раздача с удалением данных удаляет только файлы из манифеста, сохраняя исключённые и добавленные позже файлы.

## Отмена и черновик — 28 октября 2026

Во время сканирования/хеширования на странице и в старом диалоге доступна кнопка «Отменить создание». Она отправляет идентификатор задания через IPC и прокси в процесс создателя. Интерфейс ждёт фактической остановки; отмена не выдаётся за неудачное создание. Создатель прерывает чтение, дожидается закрытия потоков и убирает временный файл. Прежний выходной `.torrent` и исходники сохраняются. Блокировка задания освобождается после очистки, поэтому следующее создание можно запустить сразу.

Отмена привязана к заданию и отправившему его окну. Запоздалое нажатие после начала финального переименования не скрывает реальный результат сохранения. Кнопка на странице/в диалоге доступна до этапа записи. Проверка исходников для автораздачи остаётся отдельным этапом после сохранения; её отмена здесь не реализована.

В пакетном окне добавлена команда «Остановить пакет»: хеширование текущего элемента отменяется, следующие не запускаются. Отменённый элемент возвращается в ожидание. Если текущий файл уже сохранился и проверяется для раздачи, его результат сохраняется, очередь останавливается после него. Повторный запуск пропускает завершённые элементы.

Черновик основной страницы теперь хранит источники, имя, комментарий, приватность, размер частей, трекеры (включая намеренно пустой список), веб-сиды, автора, автораздачу, исключения, вкладку параметров и раскрытие дерева. При возвращении файлы перечитываются: устаревшее дерево/размеры не считаются достоверными, недоступный источник блокирует создание. Прогресс и результат продолжают жить вне страницы и принимают только события своего задания. «Создать ещё» очищает источники и данные текущей раздачи, сохраняя общие параметры, как прежде.

Граница хранения: черновик сохраняется при переходах между разделами до закрытия приложения. Восстановление после полного перезапуска/перезагрузки окна не входит в этот этап. Данные формы не записываются в браузерное хранилище или настройки синхронизации устройств.

Первичная проверка этапа: 45 тестов в 6 файлах без ошибок и пропусков, включая отмену до сканирования, во время хеширования и перед записью, целостность исходников/прежнего результата, повторный запуск, владение заданием, гонку поздней отмены, порядок запросов при запуске host, сохранение черновика и реальные сценарии создания/проверки/локальной передачи обоими движками. После добавления повтора раздачи набор расширен до 50 тестов; [актуальный машинный отчёт](../artifacts/torrent-draft-20261028/results.json).

`node scripts/smoke-torrent-draft.cjs` прошёл с настоящими React-компонентами и хранилищем в скрытом Electron, отдельном профиле и подставном файловом API: переходы во время настройки/работы/успеха, исключения, очищенные трекеры, недоступный источник, подтверждение остановки, поздняя отмена, старый диалог, остановка/продолжение пакета и ширина 560 px. [Отчёт UI](../artifacts/torrent-draft-20261028/ui-report.json), [черновик](../artifacts/torrent-draft-20261028/draft-restored.png), [остановка](../artifacts/torrent-draft-20261028/cancelling.png), [узкая раскладка](../artifacts/torrent-draft-20261028/draft-narrow.png).

Проверка типов Electron/renderer/guest и полная сборка прошли. Webpack сохраняет три предупреждения о размере существующих модулей/entrypoint и размещении runtime.

## Повтор раздачи и подтверждение копирования — 28 октября 2026

Сохранённый результат с ошибкой раздачи теперь содержит «Повторить запуск раздачи» на основной странице, в старом диалоге и у отдельного элемента пакета. Если автораздача была выключена, результат предлагает «Начать раздачу». Пока идёт подготовка, повторные нажатия и создание нового торрента недоступны; копирование и просмотр сохранённого результата остаются доступны. На основной странице повтор продолжает работать при переходе в другой раздел.

Повтор передаёт только непрозрачный идентификатор результата. Основной процесс хранит снимок источников, пути сохранённого `.torrent` и его infoHash; изменённый черновик/путь из интерфейса не подменяют эти данные. Движок снова проверяет метаданные по ожидаемому хешу и исходники по сохранённому манифесту. Торрент заново не создаётся. Повторная ошибка сохраняет файл, идентичность и возможность следующей попытки; успешный ответ очищает прежнюю ошибку.

Классический движок может оставить запись с ошибкой после первой проверки. При повторе возобновляется именно раздача с тем же infoHash и набором источников. Нативный движок также умеет использовать такую существующую запись. Обычная загрузка или раздача с другими исходниками не принимается за результат повтора. Уже работающая раздача повторно не добавляется.

Идентификаторы результата действуют до завершения основного процесса и привязаны к создавшему результат окну. Хранятся последние 100 результатов, включая завершённые для безопасного повторения команды; устаревший/чужой идентификатор отклоняется без запуска движка. Повтор сериализован с созданием и проверкой других раздач. Это не восстановление результатов после полного перезапуска приложения.

Страница подтверждает копирование magnet и хеша только после успешного `clipboard.writeText`. Старый диалог использует ту же логику для magnet. Пока запись ожидает ответа, кнопка блокирует повторные нажатия; отказ показывает понятную ошибку без ложного «Скопировано». Запоздалый ответ после смены результата/ухода со страницы не меняет новый экран, таймеры подтверждения убираются при размонтировании. В старом диалоге также исправлен ложный статус «раздача начата», который зависел от переключателя формы: теперь отображается фактический ответ движка.

Итоговые 50 тестов в 6 файлах прошли без ошибок и пропусков. Добавлены проверки снимка и владения результатом, отсутствия нового хеширования, сериализации повторов, ограниченного хранения, сохранения результата при ошибке и состояния при уходе со страницы. Реальные проверки обоих движков расширены сценарием «повреждённый исходник → неудачный повтор → восстановление исходника → успешный повтор → повтор той же команды → пауза → запуск из результата»: одна запись раздачи, исходники не перезаписываются, ложное завершение загрузки не отправляется.

Сценарий Electron с настоящими компонентами/хранилищем и подставным API/буфером обмена проверяет задержку, отказ и успешное копирование; подтверждение хеша; поздний ответ после ухода; повтор раздачи с ошибкой и успехом после перехода; старый диалог и отдельный элемент пакета без пересоздания торрента. [Актуальный отчёт интерфейса](../artifacts/torrent-draft-20261028/ui-report.json), [подготовка раздачи в узком окне](../artifacts/torrent-draft-20261028/seed-retry-narrow.png). Проверка типов и полная сборка также прошли; предупреждения Webpack о размере модулей/runtime остаются прежними.
