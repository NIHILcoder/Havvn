# Экспорт уникальных копий из корзины

20 октября 2026 года. «Общие файлы → Корзина → Место в корзине → Сохранить копию…». Доступно на устройстве читателя и издателя при включённом экспериментальном файловом обмене.

Кнопка сохраняет одну выбранную копию в новый обычный файл через системный выбор пути. Это побайтовый экспорт, включая двоичные данные и пустые файлы; преобразования кодировки, BOM и окончаний строк нет. Содержимое не публикуется в комнату и не добавляется в подписанную историю. После экспорта оригинал остаётся в корзине, выбор для очистки сбрасывается. Для удаления оригинала нужны отдельный выбор, новый предпросмотр и подтверждение.

## Что проверяется

Экспортируется только обычный файл `previous` в известной операции `op-…`: журнал должен быть разрешён подписанной историей, квитанция — завершённой `deleted`, набор файлов — известным, а хеш и идентичность исходных байтов — неизменными. Незавершённые, отменённые, неизвестные, связанные и занятые операции защищены. Наличие общего кеша не требуется: можно сохранить неопубликованные локальные изменения или копию, для которой недоступен старый ключ общего содержимого.

Renderer передаёт только UUID предпросмотра и идентификатор операции. Имя для диалога берётся из проверенного журнала в основном процессе. Доверенное окно и главный frame обязательны; одновременно открыт только один диалог экспорта. Отмена ничего не записывает и не расходует предпросмотр. После выбора места токен проверяется повторно, затем расходуется. Перед записью останавливается локальное фоновое обслуживание и берётся общий дисковый lock папки.

Существующие файлы не заменяются: назначение открывается с `wx+`. Ссылки, жёсткие связи, служебное хранилище приложения, приватный кеш и все подключённые общие папки исключены. Экспорт в общую папку мог бы непреднамеренно опубликовать личные правки. Права нового файла — `0600`, где ОС поддерживает этот режим; на Windows действуют также права выбранного каталога.

Копирование идёт через открытые дескрипторы блоками по 64 КиБ. Проверяются длина и SHA-256 потока, выполняется сброс на диск, затем выходной файл перечитывается. Перед фиксацией повторно проверяются исходник, назначение, каталоги, привязка, локальная очередь и контекст. Дескрипторы закрываются до подтверждения результата.

## Подтверждение отдельной копии

После успешной проверки в защищённом атомарном индексе хранится локальная квитанция: операция, папка, удалённая ревизия, размер, хеш, выбранный путь и идентичность файла. Пути и хеши личных байтов не передаются участникам. Набор прав, головы, журнал публикаций и рабочие файлы не меняются.

При новом предпросмотре выходной файл проверяется заново: точные байты, размер, идентичность и отсутствие ссылок. Только тогда появляется причина «Есть проверенная сохранённая копия вне Havvn» и становится доступен выбор для очистки. Переименование, удаление, замена, редактирование или добавление жёсткой ссылки снова защищают оригинал. Подтверждение очистки повторяет проверку, в том числе непосредственно перед удалением последних байтов корзины.

Экспортированные файлы не входят в кеш Havvn и не удаляются его квотой. После ручной очистки оригинала пользователь хранит внешнюю копию самостоятельно. Она не становится общей версией: история комнаты по-прежнему восстанавливает подписанное общее содержимое. Локальная квитанция больше не нужна после успешной очистки соответствующего payload и удаляется из индекса; сам экспорт остаётся на выбранном месте. Одновременно допускается до 2000 квитанций, без вытеснения единственных активных копий.

## Ошибки и перезапуск

Экспорт не удаляет и не перемещает исходник. При сбое выходной файл может остаться неполным; такая попытка не даёт разрешения на очистку. Если копия полностью записана, но фиксация защищённой квитанции не удалась, файл сохраняется, а оригинал остаётся защищённым. Ошибка записи индекса требует восстановления доступа и перезапуска, как остальные операции файлового обмена.

Перезапуск сохраняет проверенную квитанцию; перед очисткой внешний файл всё равно проверяется заново. Квитанции и журналы удаления в корзине сохраняют прежние правила восстановления. Ни завершение экспорта, ни запуск приложения автоматически не удаляют уникальные локальные данные.

Диалог выбора пути подменён изолированной фикстурой; файлы и основной процесс настоящие. Отчёт: `dist/room-sync-ui/evidence/trash-export-acceptance.json`; скриншоты: `trash-export-wide.png`, `trash-export-narrow.png`.
