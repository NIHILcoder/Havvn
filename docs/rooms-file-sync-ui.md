# Синхронизация папок: интерфейс и автоматические сохранения

17 октября 2026 года. Продолжение [сетевой интеграции](rooms-file-sync-network.md) и [общего плана](rooms-file-sync-plan.md).

## Как открыть

Предварительная версия остаётся выключенной по умолчанию. Для локальной проверки в PowerShell:

```powershell
$env:HAVVN_FILE_SYNC = '1'
npm start
```

В открытой комнате: настройки комнаты → «Синхронизация папок · Предварительная версия». Команда появляется только при включённой локальной capability. Одновременного редактирования и нескольких издателей в этом этапе нет.

Дополнение 18 октября: отдельная подписанная политика v2 позволяет [назначить несколько авторов](rooms-file-sync-writers.md). В списке текста появился [встроенный редактор](rooms-file-editor.md). Описание ниже относится к исходному режиму v1; совместного набора текста пока нет.

Владелец задаёт название и выбирает папку издателя. Получатель выбирает свою локальную папку для уже объявленного корня. Перед подключением показаны путь, количество включённых/пропущенных файлов, первые 100 строк и совпадения с существующими локальными путями. Само подключение не публикует файлы и не разрешает их автоматическую замену. Издатель отдельно включает автопубликацию; получатель — автоприменение.

После включения автопубликации включённые существующие файлы и будущие сохранения становятся общими. Автоприменение загружает новые версии и сохраняет прежние копии. Файлы, независимо изменённые получателем, не заменяются; конфликт отображается в списке. Доступны ручная перепроверка, открытие локальной папки и отключение без удаления файлов.

## Граница IPC

`electron/ipc/room-file-sync.ts` регистрирует отдельные обработчики состояния, страниц файлов, выбора, подтверждения и локальных действий. Разрешён только главный frame доверенного основного renderer. Страницы ограничены 100 строками, ID и значения переключателей проверяются до вызова менеджера.

Путь выбирается нативным диалогом. Renderer получает результат предварительного просмотра и подтверждает только случайный токен, ограниченный пятью минутами и текущим экземпляром сервиса. Произвольный путь назначения через API подтверждения не принимается. Проверяются fingerprint обхода, головы, политика и локальная привязка; при изменениях требуется новый просмотр. Контекст, изменившийся пока открыт диалог, не наследует старое подтверждение.

На подтверждении оба автоматических режима выключены, в том числе при повторном выборе прежнего пути. Новая привязка сбрасывает старые локальные отпечатки. Рабочая папка не может пересекаться с профилем приложения, обычными папками комнат и сохранёнными привязками других комнат текущего профиля. Приостановленные привязки также участвуют в проверке; их можно отключить локально.

Локальное поколение привязки увеличивается при её замене. Незавершённая операция не может записать отпечаток в новую привязку, даже если путь вновь совпадает. Если следующая ревизия приходит после фактической установки предыдущей, завершённая квитанция предыдущей остаётся корректной базой для следующего обновления. Прерванные операции согласуются перед следующим применением без обязательного перезапуска процесса. Эти переходы покрыты отдельными детерминированными тестами.

## Наблюдение

`RoomSyncWatcher` использует встроенный `fs.watch` как подсказку и ограниченный обход как обязательную проверку. Дополнительная зависимость Chokidar не добавлена: для текущей предварительной версии достаточно встроенного рекурсивного наблюдения с обязательным fallback. Если нативное наблюдение недоступно или ломается, обход продолжает работать раз в 10 секунд. После события повторная проверка назначается через секунду. Файл должен иметь одинаковые размер, идентичность и времена изменения в двух наблюдениях, разделённых окном стабилизации.

Проверка содержимого и подготовка публикаций сериализованы общей очередью между наблюдателями. SHA-256 открытых байтов сравнивается с отпечатком последней опубликованной версии; неизменившееся содержимое не создаёт новую ревизию. Сам снимок снова проверяется существующими механизмами и шифруется независимо. При ошибке отдельного файла остальные готовые файлы продолжают обрабатываться.

В защищённом индексе хранится локальный флаг наблюдения и очередь относительных путей. Путь удаляется из очереди вместе с фиксацией подписанной ревизии; неизменившийся файл подтверждается отдельно. Перезапуск повторяет обход и восстанавливает работу, включая изменения, сделанные пока Havvn был закрыт. Смена привязки выключает наблюдение и сбрасывает очередь прежней папки. Отключение наблюдения и закрытие комнаты останавливают watcher и отменяют ещё не разрешённые публикации.

Изменение метаданных служит кандидатом, а не доказательством изменения содержимого. Кнопка «Проверить ещё раз» сбрасывает кеш проверенных отпечатков и выполняет глубокую сверку. Обнаружение произвольной подмены с сохранением всех метаданных без глубокой проверки не гарантируется.

## Исключения и пределы

По умолчанию исключаются `.git`, `.hg`, `.svn`, `.vs`, `.idea`, `node_modules`, `bin`, `obj`, `dist`, `build`, `.havvn-*`, временные файлы, lock-файлы Office, `.env` и `.env.*`, распространённые приватные ключи и контейнеры ключей. Эти правила действуют также при автоматическом применении полученных версий. Редактор дополнительных локальных масок реализован [отдельным этапом](rooms-file-sync-filters.md).

Обход не следует символическим ссылкам/junctions и не публикует hardlinks. Лимиты: 2000 файлов на корень, 256 МиБ на файл, 10000 посещённых записей и 16 уровней каталогов. При превышении лимита обход останавливается с видимой причиной; часть папки не объявляется успешно проверенной. Некорректные имена и коллизии регистра/Unicode обрабатываются существующим валидатором.

Удаления не отправляются в сеть. Переименование в другое имя создаёт новый общий документ; прежний остаётся в подписанном индексе. Сохранение редактором через временный файл и rename обратно в прежний путь обновляет существующий документ. Наблюдатель не объединяет разветвлённую историю автоматически: публикация при нескольких головах требует отдельного разрешения конфликта.

В следующем этапе добавлены [локальные пользовательские маски](rooms-file-sync-filters.md), дополняющие встроенные исключения, с предпросмотром и причинами пропуска.

## Проверка

```powershell
npm run test:room-sync
npm run test:room-sync-ui
npm run typecheck
npm test
npm run build
```

Тесты проверяют fallback без `fs.watch`, начальный обход, rename-based save, дедупликацию, восстановление очереди, остановку до стабилизации, продолжение после ошибки отдельного файла, исключения, junctions, лимит файлов, проверку токена и недоверенных IPC-отправителей.

`test:room-sync-ui` запускает два изолированных профиля Electron с настоящими компонентом React, preload, IPC, менеджерами, DPAPI, E2E и WebRTC через локальный трекер. Только нативный выбор папки подменён на контролируемый временный каталог теста. Автоматизированы выбор/просмотр/подтверждение, отдельное включение режимов, передача двух сохранений через rename, конфликт и восстановление получателя. Отдельно проверяется автоматическая публикация после перезапуска издателя с изменением, сделанным пока он был закрыт.

Снимки широкого и узкого окна сохраняются в `dist/room-sync-ui/evidence/`. Тестовые окна остаются скрытыми; успешный сценарий удаляет собственные временные профили. Визуальная проверка выполняется по настоящим снимкам, а не по макету.

Итог проверки: 158 тестов в 10 целевых наборах; полный `npm test` — 3252 теста Vitest и 8 проверок Node без ошибок. Нативный UI/WebRTC-сценарий, включая перезапуск издателя и офлайн-сохранение, прошёл. Typecheck Electron/renderer/guest, сборки всех трёх частей и ESLint новых модулей прошли; renderer сообщает прежние предупреждения о размере bundle. Снимки широкого и узкого окна просмотрены. Физические ПК, NAT/TURN и сохранения из настоящих Office/IDE этим этапом не проверяются.
