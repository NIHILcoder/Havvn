# Стоимость тяжёлых разделов — OPT-06

Реализовано 25 октября 2026 года.

## Подтверждённая причина и изменение

`App` уже открывал конструктор темы через `React.lazy`, однако общий
`components/index.ts` одновременно экспортировал его напрямую. Загрузки
импортировали этот общий модуль, поэтому конструктор, галерея и их стили
попадали в начальную часть сборки. Плеер также импортировался напрямую
из общих компонентов и из истории просмотра.

Это проверено двумя способами: графом настоящей production-сборки без
диагностических вставок и регистрацией выполнения модулей в изолированном UI.
Комнаты и совместный редактор документов уже находились за отложенными
границами, дополнительное разделение их кода не потребовалось.

Общий экспорт плеера теперь ведёт в небольшой `LazyStreamPlayer`, а история
просмотра использует ту же границу. Настоящий `StreamPlayerModal` и зависимые
контролы загружаются при открытии. Пока код ожидается, общее окно приложения
показывает состояние загрузки; его можно закрыть. Завершение загрузки кода
после отмены не открывает плеер заново. Выбранный файл и параметры истории
передаются в настоящий плеер без изменения.

Прямой общий экспорт конструктора темы удалён. Его существующая отложенная
загрузка в `App` теперь работает. Повторное открытие использует кеш модулей,
при этом состояние закрытого интерфейса освобождается обычным размонтированием.
Работающий backend, предпочтения воспроизведения и содержимое документов
этим изменением не затрагиваются.

## Итоговое сравнение

Начальная JS-часть независимого графа: **2 086 432 → 1 641 224 байта**.
Уменьшение — **445 208 байт, 434,8 КиБ или 21,3%**. В итоговых 12 окнах новой
версии ни один из пяти наблюдаемых тяжёлых модулей не выполнялся при старте.
Граф production-режима отдельно подтверждает, что плеер, конструктор и галерея
перешли из начальных модулей в отложенные.

Медианы первого открытия по трём повторам и повторного открытия по 24 учитываемым
циклам раздела:

- комнаты: первое 177,8 → 188,2 мс, повторное 50,4 → 50,3 мс;
- документы: первое 159,0 → 158,5 мс, повторное 45,6 → 45,6 мс;
- плеер: первое 32,7 → 61,0 мс, повторное 30,6 → 30,2 мс;
- конструктор темы: первое 69,6 → 128,4 мс, повторное 50,9 → 55,7 мс.

Первое открытие плеера и конструктора стало дольше приблизительно на 28 и 59 мс:
теперь оно включает загрузку их кода. Поэтому результатом считается уменьшение
начальной загрузки и отсутствие выполнения этих модулей до запроса пользователя.
Ускорение всех разделов и уменьшение CPU работающего backend не заявляются.

В новой версии наибольший положительный прирост V8 heap за восемь циклов —
0,658 МиБ, наибольший наклон — 0,0874 МиБ/цикл; оба относятся к редактору документов.
Это наблюдаемый ненулевой дрейф в пределах описанной ниже локальной проверки.
Подписки возвращаются к прогретому состоянию, открытых сеансов документов после
закрытия нет, закрытые поверхности и буферы отсутствуют в живом DOM.

## Воспроизводимый стенд

`scripts/performance-heavy.cjs` использует настоящий `App`, страницы,
конструктор темы, CodeMirror/Yjs и плеер. Данные и API предоставлены изолированной
фикстурой; пользовательский профиль, подключения комнат и внешняя сеть
не используются. Каждый повтор запускается в новом процессе Electron
и временном профиле, каждый раздел — в отдельном скрытом окне 1200 × 850.

Проверяются четыре сценария:

- комната с 1000 файлами и 200 сообщениями, переход обратно к 100 загрузкам;
- редактор документа с заголовком и 2000 строками текста, открытие и закрытие
  реального буфера CodeMirror;
- плеер с настоящим локальным WebM 320 × 180, 15 кадров/с; продвижение видео
  проверяется отдельно от наличия элемента в DOM;
- конструктор темы с созданием черновика и отображением полей палитры,
  закрытие с освобождением места дока.

Для каждого раздела измеряется первое открытие. Затем выполняются два
прогревающих цикла и восемь одинаковых учитываемых циклов открытия/закрытия.
В каждой версии — три повтора: 96 учитываемых циклов, плюс первые открытия
и прогрев. Во время численных серий параллельные сборки и тесты не запускаются;
пользовательский dev-сервер продолжает работать.

Исходные импорты воспроизводятся в памяти двумя точечными преобразованиями
`components/index.ts` и `WatchHistoryPage.tsx`. Результат каждого преобразования
обязан совпасть по SHA-256 с первоначально сохранённым файлом, включая окончания
строк. Рабочая копия при этом не откатывается. Граф product-сборки создаётся
без регистрации выполнения модулей; этот независимый граф подтверждает состав
начальной загрузки. Рядом сохраняются исходные хеши, параметры восстановления
и отдельный хеш построенного диагностического bundle.

Сравнение требует одинаковых исходников стенда, версий runtime, оборудования,
питания, масштаба данных, порядка сценариев и числа циклов. Изменение исходников
во время серии прерывает приёмку. Кеш ОС не очищается; профиль между разделами
одного повтора уже прогрет. Числа не являются обещанием для другого компьютера.

## Учёт памяти и границы результатов

После закрытия интерфейсу даётся время завершить эффекты, затем выполняются
два диагностических GC. Записываются V8 heap, счётчики Blink, число живых DOM-узлов,
подписки API и открытые сеансы документов. Проверяются остановка опроса закрытого
редактора, возврат подписок к прогретому состоянию, закрытие сеансов и освобождение
резерва дока темы.

Общее число DOM-узлов и слушателей Blink включает отсоединённые деревья,
которые Chromium может собирать позднее. В пробной серии строгий порог этого
счётчика сработал при постоянном живом DOM. Поэтому необработанные счётчики
сохраняются для анализа отдельно. Общее число живых узлов также меняется,
когда виртуализированный фон показывает на одну строку загрузок больше или меньше
после изменения ширины дока. Проверка закрытия использует отсутствие самого окна,
буфера CodeMirror и порталов файлов комнаты, подписки и сеансы; память проверяется
по собственным выборкам heap.

В режиме `--verify` тяжёлые модули должны отсутствовать при старте, подписки
и сеансы должны возвращаться к исходному состоянию. Защитные пределы этой локальной
диагностики: прирост heap менее 2 МиБ и линейный дрейф менее 0,25 МиБ за цикл
после прогрева. Это пределы проверки регрессии,
а не утверждение о нулевых аллокациях или универсальный бюджет памяти приложения.
Все восемь выборок и наклон сохраняются, небольшой положительный дрейф не скрывается.

Размеры графа относятся к JavaScript production-режима без минификации и сетевого
сжатия. Они не равны размеру установщика. Время открытия включает управление
через `executeJavaScript`, загрузку модулей и ожидание нужного DOM; физический
показ кадра скрытого окна не измеряется. `startupMs` содержит дополнительные
300 мс стабилизации. `closeMs` включает ожидание и диагностический GC, поэтому
не используется как пользовательская задержка закрытия.

Тест не запускает настоящий torrent/room backend, транскодирование ffmpeg,
передачу документа другому участнику или GPU-приёмку. Проверка длительной работы
с реальными передачами и аппаратная приёмка остаются отдельными сценариями OPT-02.

## Проверки и повторение

```powershell
npm run test:heavy
npm run test:heavy-ui
npm run typecheck:renderer
npm run build:renderer
npm run performance:ci

# Исходный manifest хранит хеши двух файлов до изменения импортов.
npm run performance:heavy -- --runs 3 --cycles 8 --ui-before artifacts/heavy-sections/reference/source-manifest.json --output artifacts/heavy-sections/reference-v2
npm run performance:heavy -- --runs 3 --cycles 8 --verify --compare artifacts/heavy-sections/reference-v2/summary.json --output artifacts/heavy-sections/candidate-v2
```

Проверки расчётов и совместимости стенда — 15 тестов. Отдельная UI-приёмка
настоящей оболочки отложенного плеера — семь проверок: отсутствие запроса кода
при открытии страницы, состояние ожидания, отмена до загрузки, возврат фокуса,
отсутствие позднего открытия, повторное использование кода и передача параметров.
Задерживается только загрузка модуля; настоящее воспроизведение проверяется
профилирующим стендом. Русское окно проверено при ширине 480 px и масштабе 125%.
Для снимка скрытого тестового окна отключена анимация появления.

Также прошли 77 тестов из пяти файлов затронутых сценариев, проверка типов
renderer и пять структурных сценариев `performance:ci`. Production-сборка
интерфейса прошла с тремя существующими предупреждениями webpack о размере
сборки и рекомендациях оптимизации. Линтер завершился без ошибок; в существующем
`StreamPlayerModal` остаются три предупреждения о типе `any` и зависимостях hooks.

Артефакты: `artifacts/heavy-sections/reference-v2/`,
`artifacts/heavy-sections/candidate-v2/`, `artifacts/heavy-sections/lazy-player/`,
`artifacts/heavy-unit.log`, `artifacts/heavy-ui.log`, `artifacts/heavy-typecheck.log`,
`artifacts/heavy-lint.log`, `artifacts/heavy-build.log`,
`artifacts/heavy-baseline-ci.log` и `artifacts/heavy-callers.log`.
Пробные серии сохранены отдельно и не входят в итоговое сравнение.
