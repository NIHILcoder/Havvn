# Перерисовка неподвижного окна, 13 октября 2026

Пользователь сообщил о постоянных 20–30% GPU в открытом окне и почти нулевой нагрузке после сворачивания. На приложенном снимке показаны 24,6% GPU и 5,5% CPU. Это разные показатели; снимок сам по себе не доказывает частые обновления React.

## Причина и изменение

Постоянный индикатор подключения в строке состояния запускал `pulse-glow`: бесконечную анимацию `box-shadow`. Она требовала Paint и отправки кадров даже без новых данных. Такие же циклы были у индикаторов присутствия в комнате и активного звонка. Теперь все четыре индикатора сохраняют цвет и статичное свечение, без бесконечной анимации. Уменьшение анимаций также распространяется на `::before` и `::after`, включая индикатор активной загрузки.

Аппаратное ускорение, оформление стекла и частота поступления статистики в продукте не изменены.

## Проверка и воспроизведение

```powershell
node scripts/performance-idle-renderer.cjs current --verify-idle
```

Скрипт собирает настоящие App, страницы и CSS с production React profiling. Изолированный временный профиль содержит три приостановленные загрузки и комнату с 1000 файлами / 200 сообщениями; IPC синтетический, внешняя сеть заблокирована. Пользовательские загрузки, настройки и службы комнаты не запускаются. Временная папка удаляется после завершения процесса.

Окно показывается, аппаратное ускорение включено, уменьшение анимаций выключено. Только в тестовом окне `backgroundThrottling: false` не позволяет перекрытию другим окном остановить compositor. Это не изменение поведения Havvn. После прогрева каждый сценарий записывает шестисекундную CDP-трассу: события DrawFrame/Paint, вызовы React, список анимаций и CPU процессов Electron. Пробное отключение только четырёх постоянных анимаций внутри исходной сборки проверяет причинную связь.

Исходный прогон и прогон исправленной версии сохранены в `artifacts/performance-idle/before.json` и `after.json` вместе с временем, длительностями и хешами исходников. Они запускались последовательно. GPU исправленного прогона: RTX 2060, ANGLE D3D11, аппаратный compositor и rasterization включены.

- Неподвижные загрузки, обычная тема: **867 → 0 DrawFrame** за сценарий.
- Неподвижные загрузки, стекло Aero: **868 → 0 DrawFrame**.
- Неподвижная комната, стекло Aero: **871 → 0 DrawFrame**.
- В исходной сборке одно экспериментальное отключение постоянных анимаций также давало **0 DrawFrame** в загрузках и комнате, без изменения стекла.
- React выполнял **0–1 commit** за сценарий, а не обновлялся на каждом кадре.

`--verify-idle` проверяет отсутствие непрерывной перерисовки, статичное свечение всех четырёх индикаторов, уменьшение анимации псевдоэлемента на отдельном образце с настоящими CSS-правилами, восстановление после выключения этой настройки, обновление статуса настоящей строки загрузки и открытие/закрытие графика скоростей. Небольшой допуск на случай разового обновления не допускает поток кадров.

## Границы результата

Около 144 кадров/с в исходном прогоне соответствуют частоте монитора этого компьютера. Отсутствие DrawFrame в шестисекундном неподвижном сценарии не обещает 0% GPU при любых действиях: загрузки, прокрутка, ввод, открытие меню, графики, голос и видео могут вызывать необходимую отрисовку. Этот тест не измеряет столбец GPU Диспетчера задач, настоящую сеть или произвольные пользовательские темы. CPU GPU-процесса в JSON тоже не является процентом загрузки видеокарты.

Предыдущая методика из `renderer-performance.md` использовала скрытое окно, программный GPU и уменьшение анимаций; для данного сообщения о видимом окне она недостаточна.

Источники по интерпретации показателей: [Microsoft: GPUs in the Task Manager](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/), [Electron: BrowserWindow backgroundThrottling](https://www.electronjs.org/docs/latest/api/browser-window/).
