# Явное удаление и корзина общих файлов

20 октября 2026 года. Экспериментальный протокол v6 добавляет явную команду удаления в Havvn. Функция остаётся за `HAVVN_FILE_SYNC=1`.

Владелец открывает настройки общей папки → «Кто может редактировать», включает «Разрешить удаление с корзиной», проверяет выбор и подтверждает его. Переход на v6 необратим; назначенные авторы должны поддерживать v6. Старые клиенты перестают получать этот корень. Как и при других сменах политики, автоматические режимы отключаются до повторного включения на каждом устройстве.

У автора появляется кнопка удаления рядом с файлом в «Общих файлах» и в настройках папки. Подтверждение показывает путь и размер локальной копии. Подписанная ревизия `delete` не содержит blob; она покрывает проверенные текущие головы того же `entryId` и пути. Независимые ветви редактирования не скрываются и разбираются через историю. Восстановление содержимого создаёт новую подписанную ревизию `put` поверх текущих голов; это действие доступно автору с правом записи.

Получатель применяет удаление только в подключённой папке с включённым автоматическим получением. Само получение метаданных ничего не удаляет. Если локальные байты отличаются от применённой базы, действие останавливается. В диалоге разбора можно принять удаление с сохранением байтов в корзине либо «Сохранить обе»: дополнительно создаётся отдельный файл в `.havvn-local/copy-…/`.

Рабочие байты атомарно переносятся в `.havvn-sync/trash/op-…/previous`. Рядом сохраняются журнал и квитанция. Перезапуск различает подготовленный журнал без переноса, выполненный перенос, позднюю запись по старому файловому дескриптору и новый файл на прежнем месте. Новые файлы не перезаписываются; неоднозначные байты остаются для явного разбора. Журнальные пути проверяются по подписанной ревизии удаления и её предку с содержимым; ссылки, жёсткие ссылки и опасные относительные пути отклоняются.

Корзина имеет лимит 2 ГиБ на локальную папку. Место проверяется до публикации удаления и повторно перед переносом; при заполнении новое удаление блокируется. Автоматической очистки корзины нет. Очистка резервных копий не затрагивает корзину, а очистка приватного кеша сохраняет проверенные снимки, которым соответствуют оставшиеся локальные копии в корзине. При недоступной локальной привязке очистка кеша приостанавливается. Восстановление через историю работает и при нулевом лимите кеша. Квоты корзины и защищённого кеша считаются отдельно.

Если после публикации намерения локальный перенос не удался, например из-за блокировки файла, запись видна в списке файлов как ошибка с командой разбора и явного повтора. Автоматическое получение автора для этого включать не требуется.

Удалённые записи доступны через «Корзина» рядом с общей папкой. Страницы живых и удалённых записей формируются отдельно на стороне главного процесса. История явно отмечает ревизии удаления; их нельзя выбрать как версию с содержимым. Подписанные контрольные снимки сохраняют v6 и текущие удаления.

## Проверки

Тесты файлового слоя проверяют прерывание на каждом шаге, повторное восстановление, позднюю запись, новый файл по старому пути, подделку полномочий журнала, ссылки и переполнение корзины. Тесты сессии проверяют обычную и E2E-комнату, восстановление после перезапуска, устаревший предпросмотр, локальные правки, edit/delete, коллизию разных `entryId`, checkpoint и защиту старых снимков при очистке кеша. Координатор проверяет согласование v6, одноразовые подтверждения, страницы корзины и отсутствие загрузки blob при удалении. IPC принимает идентификаторы и строгие логические параметры только из доверенного окна.

`npm run test:room-sync-deletes` проверяет интерфейс в настоящем Electron: включение владельцем, кнопку в общих файлах, подтверждение, блокировку Windows с повтором, корзину, восстановление через историю, сохранение независимых правок, перезапуск и нулевой кеш. Снимки сохраняются в `dist/room-sync-ui/evidence/delete-*.png` и `trash-library.png`. Используются изолированные профили на одном физическом ПК.

## Оставшиеся границы

Удаление файла в Проводнике не публикуется автоматически. Добавлен [отдельный список внешних удалений](rooms-file-sync-missing.md) с повторным обходом, защитой от массовой потери и подтверждением по одному файлу. Добавлено [управление местом в корзине](rooms-file-sync-trash-storage.md) с очисткой только при наличии проверенной независимой копии. [Уникальные локальные копии можно экспортировать](rooms-file-sync-trash-export.md), а оригинал очистить отдельным действием. Не добавлены массовое удаление и удаление каталогов. Для коллизий путей теперь доступно окно [«Разобрать имена»](rooms-file-sync-paths.md). Проверки между физическими ПК, через внешние NAT и с Office/IDE ещё не выполнены.
