# Создание и автораздача: исправления 27 октября 2026

## Причина

Предыдущее описание было слишком широким: новые записи с сохранённым `.torrent` уже добавлялись через `client.add`. Повторная сборка через `client.seed` оставалась в старом пути без метаданных. Дополнительно обнаружены неполное сопоставление нескольких источников, зависимость от пользовательского выходного файла и опасное рекурсивное удаление исходных каталогов.

## Реализовано

- Метаданные перед автораздачей проверяются по infoHash результата создания и сохраняются отдельным файлом в профиле. Перемещение пользовательского `.torrent` не ломает новые записи раздачи. Записи без исходных метаданных требуют повторного создания, вместо незаметной генерации другого торрента.
- Классический движок сопоставляет каждый файл манифеста с выбранным источником. Поддерживаются одиночные файлы, папки, смешанные и разрозненные источники, пользовательское имя корня и исключения. Для чтения используются точные пути; проверяются границы выбранных каталогов, размеры и повторяющиеся пути.
- Хранилище исходных файлов классического движка запрещает запись и удаление данных со стороны chunk-store. До подключения к пирам проверяется наличие всех частей. Изменения файлов при чтении приводят к ошибке, а не к загрузке поверх исходников.
- Нативный движок добавляет метаданные на паузе, останавливает автоматическую проверку, меняет корневое имя в пустом служебном каталоге и переключает расположение без перемещения данных. Затем сверяет хеши и объём проверенных данных перед запуском. Этот же путь используется при восстановлении и повторном запуске записей раздачи.
- Ошибка автораздачи не скрывает успешное сохранение `.torrent`. В интерфейсе видна отдельная стадия проверки исходников без фиктивного процента.
- При удалении данных раздачи используются только файлы её манифеста. Исходные каталоги целиком не удаляются; исключённые и появившиеся позже файлы сохраняются.
- Создатель потоково читает явный список файлов без временных копий содержимого. Скрытые обычные файлы включаются, ссылки пропускаются, исключения и выходной `.torrent` учитываются. Проверяются изменения размера, идентичности и времени изменения файлов до/после чтения и перед записью.
- Итоговые метаданные сохраняют точную структуру списка файлов, в том числе папки с единственным файлом. Запись результата выполняется во временный файл в том же каталоге с последующим переименованием. Ошибка записи не обрывает существующий файл результата.
- Пятиминутное ограничение хеширования заменено контролем отсутствия прогресса. Параллельные запросы создания блокируются до окончания подготовки автораздачи. Установлены пределы размера метаданных и количества файлов.

## Ограничения

Transmission требует одного физического корня с соответствующей структурой содержимого. Несколько соседних файлов/папок поддерживаются; произвольные источники из разных каталогов или дисков требуют классического движка. В таком случае файл торрента остаётся сохранённым, а автораздача возвращает понятную ошибку. Автоматического переключения движка или полного копирования исходников нет.

Нет отдельной кнопки отмены хеширования и команды повторной автораздачи из результата. Это дальнейшие улучшения интерфейса.

## Проверка

После отдельного разрешения пользователя выполнены функциональные проверки: настоящий создатель, WebTorrent, комплектный Transmission и передача файлов через localhost в отдельных временных профилях. Добавлены постоянные регрессионные тесты в `creator.test.ts`, `creation-seeding.test.ts`, `native/native-manager.test.ts` и `shared/torrent-creation.test.ts`.

Проверены переименование корня; папка с единственным вложенным файлом; смешанные и разрозненные источники; скрытые/пустые файлы и исключения; private/source и размер частей; независимое вычисление infoHash и хешей частей; изменение исходника во время создания; повреждение содержимого перед раздачей без изменения размера; пауза/возобновление; восстановление удалённой записи; удаление при наличии исключённых/новых файлов; неуспешная запись результата. Сценарии нативного ожидания проверки включают устаревший снимок статистики и паузу во время подготовки.

Тест полного цикла выявил ложное уведомление о завершении после возобновления созданной нативной раздачи. Исправление: после проверки сохраняется `progress=1`, а у новой раздачи инициализируется время начала сидирования. Проверка старых записей также восстанавливает полный прогресс до возобновления. Сценарии обоих движков после исправления проходят без повторного уведомления.

Проверки интерфейса вручную, передача на второй физический компьютер, нагрузка многогигабайтными источниками и реальное заполнение диска не входили в этот запуск. Подробный итог и границы проверки: [отчёт](torrent-creation-tests-20261027.md).

При реализации ожидания проверки изучен [исходный код Transmission](https://github.com/transmission/transmission/blob/4.0.6/libtransmission/torrent.cc): после проверки значение её прогресса сбрасывается, поэтому завершение определяется состоянием и количеством проверенных байтов. Переименование также требует предварительной остановки и безопасного расположения содержимого.
