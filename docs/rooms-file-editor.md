# Встроенный редактор файлов: первый прототип

20 октября добавлен отдельный [совместный редактор документов](rooms-documents.md) с курсорами, офлайн-очередью, вкладками, Markdown и локальными снимками. Вход: «Общие файлы → Общие документы → Открыть редактор». Кнопка файлового редактора «Создать общий документ» создаёт самостоятельную копию текста. Для файлов также добавлена подсветка C#, JS/TS, YAML, TOML, CSS, HTML, SQL, shell, PowerShell и конфигов. Описанные ниже гарантии записи обычных файлов продолжают действовать независимо от совместных документов.

18 октября 2026 года. В списке файлов подключённой папки появилась команда «Открыть в редакторе» для поддерживаемого текста. Функция следует экспериментальному флагу синхронизации и не включает его автоматически.

20 октября: основной вход перенесён в раздел комнаты **«Общие файлы» → «Общие рабочие папки»**. Нажмите на папку, затем «Открыть в редакторе» у нужного файла. Рядом доступна история этого файла, а кнопка настроек справа от папки открывает управление подключением. Неподключённая папка тоже видна: можно просмотреть список и историю, затем явно выбрать локальный каталог через «Подключить». Сам просмотр ничего не записывает на диск.

В настройках папки оставлены основные действия и отдельные строки автоматической публикации/получения. Смена каталога, права, исключения, кеш, резервные копии и служебные операции сгруппированы в раскрывающемся блоке «Настройки папки». Интерфейс использует текущую тему Havvn.

Интерфейс на [CodeMirror 6](https://github.com/codemirror/basic-setup/blob/main/src/codemirror.ts): номера строк, отмена/повтор, поиск и замена, перенос длинных строк, `Ctrl+S`, копирование буфера и перечитывание файла. Подсветка Markdown, JSON и XML; конфиги, исходники и остальные явно перечисленные текстовые расширения открываются как текст. Цвета используют тему Havvn, тексты — RU/EN. Код редактора загружается отдельным ленивым чанком при открытии.

Поддерживается только корректный UTF-8 до 1 МиБ. BOM и единый LF/CRLF сохраняются. Двоичные управляющие символы, UTF-16/невалидный UTF-8, смешанные окончания строк, нестабильные файлы, ссылки и большие файлы отклоняются. `.docx` и `.xlsx` остаются файлами для внешних приложений.

Главный процесс выбирает файл по `rootId` и `entryId` внутри уже подтверждённой привязки. Renderer не передаёт путь или право записи. Чтение ограничено размером даже при росте файла; проверяются дескриптор, тип, число ссылок и идентичность пути после чтения.

Для записи нужны актуальные права автора, применённая исходная версия и разрешённый файл. Получатель может открыть локальный файл для чтения. Локальный файл вне снимка владельца тоже доступен для чтения и копирования. Неоднозначные текущие ветви сначала разбираются через историю.

Открытие выдаёт одноразовый серверный токен на 30 минут, связанный с политикой, головами, исходной применённой версией, привязкой, её поколением и SHA-256 рабочих байтов. Сохранение заново проверяет эти условия и ограничения текста. Дальше используются неизменяемая копия, E2E-шифрование, подписанная ревизия, исходящая очередь, журнал применения и резервная копия. Неизменённые байты не создают новую ревизию. После сохранения выдаётся новый токен; watcher узнаёт сохранённый отпечаток и не создаёт обратный цикл.

Внешнее сохранение, новая общая версия, исключение пути, смена прав или привязки блокируют устаревшее сохранение. Ошибка оставляет текст в открытом буфере, доступны копирование и явное перечитывание. Закрытие/перечитывание изменённого буфера требуют подтверждения отбрасывания. Черновик пока находится в памяти окна и не переживает завершение процесса; автосохранения черновиков нет.

## Проверки и граница прототипа

`npm run test:room-sync-editor` проверяет в настоящем Electron ввод в CodeMirror, сохранение Markdown и шифрованную доставку второму профилю, отсутствие выполнения исходной HTML-разметки, чтение без права записи, внешнее изменение файла, сохранность отклонённого черновика и подтверждение закрытия. Снимки интерфейса: `dist/room-sync-ui/evidence/editor-wide.png` и `editor-narrow.png`.

`npm run test:room-sync-library` проверяет настоящий `RoomFilesPanel` с общей рабочей папкой и 35 обычными файлами: раскрытие папки, редактор и сохранение с доставкой второму профилю, прямой переход к истории, чтение без права записи и просмотр неподключённой папки без неявной привязки. Проверяются прокрутка смешанного списка, размеры кнопок, отсутствие горизонтального переполнения и положение переключателя; снимаются широкое и узкое окна, включая синюю тему с округлёнными элементами. Снимки: `dist/room-sync-ui/evidence/library-*.png` и `folder-settings-*.png`. Проверка использует три изолированных профиля на одном ПК.

Тесты сессии проверяют BOM/CRLF, отсутствие лишней ревизии, резервные байты, E2E, блокирование записи читателем, изменение политики и исключения. Тесты файлового адаптера проверяют кодировки, смешанные окончания, размеры и жёсткие ссылки. Тесты координатора проверяют одноразовые токены и выдачу нового токена после сохранения.

Это редактор локального файла с публикацией сохранённой версии. Одновременный набор текста, чужие курсоры, CRDT-журнал, автоматическое слияние и создание новых файлов внутри редактора пока не реализованы. Совместные заметки из шага 7 [общего плана](rooms-file-sync-plan.md) должны получить отдельный `documentId`, устойчивый журнал и проверяемый сетевой провайдер; рабочие файлы станут явным импортом/экспортом таких документов.
