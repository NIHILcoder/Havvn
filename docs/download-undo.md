# UX-04: отмена удаления загрузки

Реализовано 23 октября 2026 года для Native и Classic.

## Поведение

После удаления записи с сохранением файлов появляется общая панель
«Удалено из списка» с кнопкой «Отменить». Она остаётся доступной при переходе
на другие страницы. На каждую запись отводится 30 секунд текущего сеанса.
Перезапуск приложения очищает журнал. Удаление вместе с файлами отмену
не предлагает; предпросмотр такого удаления и системная корзина остаются
отдельной задачей.

Восстанавливаются прежний ID и дата создания, источник и infoHash, каталог,
выбор и приоритеты файлов, категория, приоритет записи, последовательный режим,
параметры скорости и раздачи, правки трекеров и накопленные счётчики.
Поддержка самих параметров движками остаётся прежней. Удалённая за это время
категория заменяется отсутствием категории с пояснением.

Исходная пауза сохраняется. Для активной загрузки проверяются текущие условия
VPN, свободное место и достигнутые лимиты раздачи. При блокировке запись
возвращается на паузе с объяснением. Условия проверяются перед подготовкой
движка и повторно перед автоматическим возобновлением после проверки диска.
Предыдущая ошибка возвращается как ошибка, завершённая запись — как завершённая
после успешной проверки данных. Если защитные условия запрещают подготовку
движка, восстанавливается только запись на паузе.

## Метаданные и данные на диске

До удаления сохраняется внутренний снимок записи и метаданных `.torrent`.
Исчезновение исходного `.torrent` не мешает Undo: восстановление создаёт новую
копию метаданных в каталоге профиля. Для Native магнитные метаданные также
читаются из собственного хранилища daemon. Неразрешённый magnet можно вернуть
без метаданных, если размер и файлы ещё не были известны.

Исправление 29 октября: в Native команда «Удалить с файлами» также удаляет
нерабочий magnet, который ещё не получил метаданные и не имеет данных для
удаления. Нулевое состояние проверяется по записи и свежему ответу daemon;
удаление выполняется по infoHash, без подбора путей по отображаемому имени.
Для записи с известными/ранее скачанными данными защита от удаления без
метаданных сохраняется. Регрессия проверена для активной привязки и
восстановленной записи; отдельный тест с настоящим daemon подтверждает
сохранность посторонних файлов и одноимённой папки. Целевые 76 тестов Native,
журнала и IPC и отдельная проверка настоящего daemon прошли.

Проверяются конфликты ID и infoHash, включая hex/base32 magnet, существование
прежнего каталога и сохранённых файлов. Отсутствующие или уменьшившиеся файлы
не создаются автоматически: пользователь получает причину и может повторить
Undo до истечения окна. Движок проверяет содержимое имеющихся файлов. Если
исправных данных стало меньше, запись остаётся на паузе с предупреждением.

Classic откладывает поиск пиров и обращения к трекерам до разрешённого
возобновления. Пауза WebTorrent сама по себе не блокирует discovery, поэтому
при проверке используется отдельный адаптер отложенного discovery.
Native добавляет торрент остановленным и подтверждает завершение проверки
диска по состоянию daemon. Незавершённая за 60 секунд проверка оставляет запись
на паузе с предупреждением; истечение ожидания не отменяет работу daemon.

Оба движка используют сохранённые метаданные и исходные пути файлов раздачи,
включая каталог с именем, отличающимся от имени торрента. Новый торрент из
файлов не создаётся: сохраняются infoHash и прежний отсчёт времени раздачи.
Для Native сохраняется база накопленных счётчиков, поскольку удаление записи
из daemon сбрасывает его локальные счётчики; лимит раздачи учитывает эту базу.

## Границы и ошибки

- Журнал хранится в main, только в памяти: до 20 записей и 64 МиБ оценённого
  размера снимков; метаданные ограничены 8 МиБ и 10 000 файлов.
- Более старые снимки вытесняются при достижении лимита. Выполняющееся Undo
  сохраняется до подтверждённого результата даже после исходных 30 секунд.
- Renderer получает токен, имя, срок и состояние операции, без источников,
  путей или метаданных. IPC принимает запросы только текущего главного frame.
- Повторные нажатия объединяются в одну операцию. Подтверждённый результат
  остаётся доступным ещё 5 секунд; повторное Undo не создаёт вторую запись.
- Ошибка удаления не создаёт кнопку Undo. Если невозможно подготовить снимок,
  удаление с сохранением файлов завершается с явным предупреждением.
- Массовое удаление учитывает результат каждой записи: неудачные остаются
  выделенными, ошибка видна над панелью Undo.
- Ошибка записи метаданных или вставки в store не выдаётся за восстановление;
  удаляется только новая служебная копия метаданных. Ошибка последующей
  подготовки движка сохраняет восстановленную запись с пояснением.

## Проверка

`npm run test:download-undo` проверяет журнал, доверие IPC, скрытие снимка,
повторы, конфликты, текущие защиты и состояние renderer. Настоящие Classic
и Native выполняют удаление/восстановление на изолированных данных без внешних
пиров: исходная пауза, раздача, собственное имя каталога, приоритеты файлов,
счётчики, отсутствие повторного уведомления и побайтовая сохранность файлов.
Также проверяются исчезнувшие данные/каталог, повреждённые метаданные и откат
служебной копии при отказе store.

`npm run test:download-undo-ui` использует настоящий Electron, production
preload, общий журнал и реальные компоненты App, строк загрузок, подтверждения
и панели Undo. Граница движка в этом UI-тесте подменена; настоящие движки
проверяются отдельными тестами выше. Проверяются навигация, повтор после ошибки,
ожидание операции, частичный отказ массового удаления, ширина 520 px и en/ru.
Снимки: `dist/download-undo-ui/wide.png`, `narrow.png`; отчёт: `report.json`.

Общий регрессионный прогон перед финальными уточнениями: 3857 тестов Vitest
и 8 проверок запуска прошли. После уточнений прошли 25 проверок Undo,
79 проверок Native manager/map и 15 UI-проверок. Снимки широкого и узкого окна
просмотрены. Typecheck Electron/renderer/guest и сборки прошли; renderer
сохраняет три предупреждения webpack о размере и runtime чанков.

ESLint новых модулей прошёл. В существующих Classic/Native manager остаются
прежние `no-require-imports`; чистый общий lint не заявляется. Настоящие
VPN-сети, внешние трекеры, производительность проверки больших дисков
и поведение системной корзины здесь не проверяются.
