## Подготовка ручного прогона

На обоих ПК использовать одинаковый снимок исходников и сборку. Профили между ПК не копировать: каждый создаёт собственную идентичность и защищённые ключи. На каждом ПК нужны зависимости проекта и обычная локальная сборка:

```powershell
npm ci
npm run build
npm run room-sync:acceptance -- prepare D:\HavvnSyncPilot
```

Последняя команда создаёт только новый каталог; при существующем пути останавливается. Внутри находятся `publisher`, пустой `receiver` и `reports`. Исходные данные: конфиг, Markdown, пустой файл, путь с пробелами/кириллицей и небольшой C#-проект с `.sln`/`.csproj`. Три синтетических исключения: `.env`, файл в `obj` и имя lock-файла Office. Это безопасные тестовые строки, без настоящих ключей или настроек. На ПК издателя используется `publisher`, на втором ПК — пустой `receiver`.

Для изолированного запуска из корня репозитория после сборки:

```powershell
$env:HAVVN_FILE_SYNC = '1'
$env:TH_INSTANCE = 'file-sync-pilot-publisher' # на втором ПК: file-sync-pilot-receiver
& .\node_modules\.bin\electron.cmd . '--user-data-dir=D:\HavvnSyncPilot\profile'
```

Фактический профиль первого ПК — `D:\HavvnSyncPilot\profile-file-sync-pilot-publisher`, второго — соответствующий суффикс receiver. Обычный профиль Havvn сохраняется. Изолированные экземпляры не меняют системный автозапуск Havvn и не регистрируют обработчики `magnet:`/`havvn:`. Приглашение передавать вручную через окно входа в комнату. Чтобы перезапустить ту же тестовую личность, использовать ту же команду и суффикс. Для завершения выбрать «Выход», а не оставлять процесс в трее.

Если второй ПК ещё недоступен, оба экземпляра можно запустить в двух терминалах на одном ПК с разными суффиксами. Это полезно для ручной работы с редакторами, но не заменяет сетевую приёмку на двух устройствах.

## Порядок ручной проверки

1. Создать приватную E2E-комнату на ПК издателя, войти со второго ПК. Подключить `publisher` и `receiver` через предпросмотр. До отдельного включения автопубликации/автоприменения файлы на получателе не появляются. После включения дождаться состояния «Применено» для всех семи исходных файлов. Убедиться, что `.env`, `obj` и `~$office-lock.docx` отсутствуют у получателя.
2. Открыть `config.ini` и `notes.md` обычным редактором на издателе. По очереди изменить, сохранить и дождаться доставки. Проверить серию из нескольких сохранений. Открыть C#-проект установленной IDE, изменить `Program.cs`, сохранить; убедиться, что сборочные `bin`/`obj` не появились у получателя. Компиляция проекта не является требованием синхронизации.
3. Создать настоящие `pilot.docx` в Word и `pilot.xlsx` в Excel внутри папки издателя. Записать известный текст и значение ячейки, сохранить и закрыть документы. Проверить открытие у получателя и повторное сохранение издателем. Повторить при открытом документе на получателе: в зависимости от режима Office обновление может примениться или отложиться из-за блокировки. При блокировке прежние байты сохраняются; после закрытия и перепроверки обновление должно примениться без потери локальных правок. Сам Word/Excel не обязан перечитать уже открытый документ без повторного открытия.
4. Пока файл открыт у получателя, внести туда независимые правки и сохранить. Затем сохранить другую версию у издателя. Должен появиться конфликт. Проверить «Отложить» и перезапуск, затем «Сохранить обе». Убедиться, что локальная версия сохранена отдельно в `.havvn-local`, принята общая версия и следующее обновление применяется автоматически.
5. Отключить сеть только на втором тестовом ПК обычным способом. Сделать три сохранения издателем, дождаться публикации каждого. Восстановить сеть: получатель должен принять последнюю версию и показать все три записи истории. Повторить с закрытым Havvn у получателя. Для проверки NAT повторить через разные сети; отсутствие второго устройства/другой сети фиксировать как «не проверено».
6. Восстановить старую версию издателем через историю. У получателя должна появиться новая ревизия с прежним содержимым. Проверить очистку приватного кеша и резервных копий через их предпросмотр: защищённые текущие копии, журналы и `.havvn-local` остаются; после перезапуска следующее изменение снова доставляется.
7. Включить нужную политику владельцем через предпросмотр прав. Явное переименование сохраняет `entryId` в v3+, явное удаление через Havvn доступно с корзиной в v6. На тестовом файле проверить переименование, удаление, корзину и восстановление через историю. Удаление в Проводнике не публикуется автоматически: для него есть отдельный разбор. Несколько авторов и совместные документы имеют дополнительные сценарии в [rooms-file-sync-writers.md](rooms-file-sync-writers.md) и [rooms-documents.md](rooms-documents.md); один этот ручной прогон их полную приёмку не закрывает.

## Сверка байтов и результат

Закрыть редакторы и дождаться применения. На каждом ПК снять манифест соответствующей рабочей папки, записав отчёт за её пределами:

```powershell
# Издатель
npm run room-sync:acceptance -- manifest D:\HavvnSyncPilot\publisher D:\HavvnSyncPilot\reports\publisher-final.json
# Получатель
npm run room-sync:acceptance -- manifest D:\HavvnSyncPilot\receiver D:\HavvnSyncPilot\reports\receiver-final.json
```

Передать только эти отчёты на один ПК и сравнить:

```powershell
npm run room-sync:acceptance -- compare D:\HavvnSyncPilot\reports\publisher-final.json D:\HavvnSyncPilot\reports\receiver-final.json
```

`equal: true` и код выхода 0 подтверждают совпадение относительных путей, размеров и SHA-256 включённых файлов на момент съёмки. Код 1 и `differences` показывают отсутствующие файлы или отличающееся содержимое. Исключения и резервные копии не сравниваются; совпадение не доказывает доставку истории, работу Office или независимость устройств. Манифесты содержат имена файлов и их отпечатки, но не содержимое; передавать их только участникам проверки. Файлы отчётов не перезаписываются. Если во время хеширования сохранён файл, снимок отклоняется; после паузы повторить с новым именем отчёта.

Для результата записать версии Windows, Havvn и редакторов, число физических ПК, одну/разные сети, выполненные шаги и не проверенные условия. При ошибке сохранить точный шаг, время, состояние строки файла и отдельные исходные байты; не очищать историю до разбора. Встроенную диагностику комнаты можно экспортировать локально, но профиль, приглашение и ключи к отчёту не прикладывать. До реальной проверки на двух ПК критерий пользовательского выпуска остаётся открытым.
