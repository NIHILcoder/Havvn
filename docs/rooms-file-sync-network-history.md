# Получение архивной истории у участников

19 октября 2026 года. В окне истории появилась кнопка «Получить раннюю историю». Она запрашивает метаданные прежних эпох всей папки, включая старые пути и подписи. Загрузка выполняется явно; обычная синхронизация продолжает передавать только активную эпоху.

## Проверяемая цепочка

Получатель начинает с уже принятого контрольного снимка владельца. Тот подписывает SHA-256 множества ID предыдущего журнала, его число записей, ID предыдущей политики, предыдущий checkpoint ID и текущие головы. Архив принимается только при совпадении этих обязательств. Все его политики, ревизии и встроенные головы отдельно проходят проверку подписей, авторства, контекста комнаты/корня, E2E, причинных связей и прежних прав. Проверяются также завершающая политика, набор голов и поколение предыдущего снимка.

Восстановленный предыдущий снимок задаёт запрос следующей, более старой эпохи. Так загрузка идёт назад по подписанной цепочке. Простого наличия корректных старых подписей недостаточно, чтобы подмешать посторонний набор записей. Распакованные данные нормализуются: неизвестные неподписанные поля не сохраняются.

Источник может быть любым совместимым участником, сохранившим точный журнал с указанной контрольной суммой. Офлайн-устройство со своими дополнительными ветвями может иметь другой архив той же эпохи: оно сохраняет эти ветви локально, но не выдаёт их за журнал, заверенный владельцем. Если точной копии ни у кого нет, цепочка остаётся неполной и интерфейс сообщает недоступность; уже загруженные эпохи сохраняются.

## Сеть и ограничения

Используется отдельная capability и тип конверта `file-sync-history-v1`; корень v4 можно оставить на v4. Старые клиенты продолжают обычный обмен, но не служат источниками этого протокола. Capability объявляется только при включённой экспериментальной синхронизации. Для конверта используется подписанный домен v5 с отдельными видами `history-request`, `history-part`, `history-missing`; подмена на обычный конверт v5 или прежнюю версию запрещена.

Запрос содержит случайный ID операции, корень, checkpoint ID, обязательство архива и байтовое смещение. Ответ связывает эти поля с точным размером, SHA-256 передаваемой упаковки и байтами части. Запрашиваются gzip-упаковки метаданных; сжатие не освобождает от проверки подписей или лимита распаковки. В них нет локальных привязок, путей кеша, разрешений записи и очереди отправки.

- Тело сообщения не превышает 96 КиБ; одна часть содержит 48 КиБ исходных байтов, последняя может быть короче. Запись для передачи ограничена 8 МиБ.
- В комнате одновременно загружается один исторический архив, от одного выбранного источника. Ответы других участников не смешиваются с его частями. Исходящий кеш хранит одну упаковку, не больше 8 МиБ.
- Потерянная часть повторно запрашивается с ожидаемого смещения каждые 2 секунды. После 6 секунд без прогресса выбирается другой доступный источник и сборка начинается заново. Полный срок одной попытки эпохи ограничен 20 секундами. Ошибка отправки одному адресату не мешает спросить остальных.
- Перезапуск отбрасывает незавершённую сборку. Полностью проверенные и атомарно сохранённые эпохи остаются; следующий запрос продолжает с первой ещё недоступной эпохи.
- Сохраняется до 8 скачанных эпох отдельно от 8 собственных архивов. Общий защищённый снимок по-прежнему ограничен 16 МиБ, каждый распакованный журнал — 16 МиБ. При достижении квоты удаление не выполняется. Лимит страниц истории расширен до 17 бюджетов по 10 000 ревизий, включая обе группы и активную эпоху.

## Локальное хранение и восстановление

Схема хранилища v4 добавляет отдельный проверяемый массив скачанных эпох. Старые схемы 1–3 читаются без автоматической загрузки истории. После загрузки для открытия локального хранилища требуется обновлённый Havvn; старый клиент отклоняет неизвестную схему. Перезапуск повторно проверяет всю сохранённую цепочку. Атомарная замена оставляет полный старый или новый снимок при отказе записи; неоднозначная ошибка блокирует экземпляр до повторного открытия.

Импорт не меняет активную политику, головы, исходящую очередь, рабочие файлы, отпечатки применённых версий, привязку и автоматические режимы. История объединяется с локальными архивами по эпохам и удаляет повторы заверенных голов. Обычные изменения прав, новые checkpoints и локальное gzip-уплотнение сохраняют скачанную историю.

Метаданные показывают существование версии; наличие её байтов проверяется отдельно. Для восстановления участник должен иметь текущие права записи, привязанную папку и подходящую текущую голову файла. Выбранные байты запрашиваются через прежний проверяемый blob/E2E-транспорт, проходят проверку торрент-метаданных и расшифровку. Только подтверждение предпросмотра создаёт новую ревизию текущей эпохи и заменяет рабочую копию с резервной версией. Одна загрузка истории не даёт прав на запись и не публикует старые ревизии как новые активные.

## Проверки

Модульные сценарии покрывают две эпохи, 400 подписанных версий, открытый и E2E-режимы, сохранность файлов и согласия, повторное открытие, подмену и пропуск записей, чужие офлайн-ветви, атомарные ошибки до/после записи, квоту в восемь эпох, потерю/повтор частей, таймер повторов, смену источника и проверку сетевого конверта. Проверка координатора начинает с чистого профиля, загружает историю без привязки, затем явно восстанавливает старую версию с передачей её байтов. IPC проверяет отправителя, главный frame и UUID.

`npm run test:room-sync-history` запускает три изолированных Electron-профиля. Проверяется загрузка двух эпох из окна истории у участника, когда владелец офлайн, отсутствие привязки и записи до согласия, перезапуск нового профиля, получение выбранных старых E2E-байтов и публикация новой восстановленной версии. Снимки: `dist/room-sync-ui/evidence/history-network-wide.png` и `history-network-narrow.png`.

Один физический Windows-ПК, loopback WebRTC. Внешние NAT, два физических ПК и настоящие Office/IDE остаются отдельной приёмкой. Функция остаётся экспериментальной; экспорт/очистка архивных метаданных, удаления и CRDT-редактор ещё не реализованы.

Итог 19 октября: **253 набора / 3483 теста Vitest прошли** на неизменяемых исходниках; дополнительно прошли 8 тестов запускателей. Проверки типов Electron, renderer и guest, линтер изменённых модулей и все три сборки завершились без ошибок. В существующих крупных модулях остаются предупреждения линтера, production renderer сообщает 3 предупреждения сборщика. Нативный сценарий `--ui --history` прошёл полностью, узкий и широкий интерфейсы проверены по снимкам.
