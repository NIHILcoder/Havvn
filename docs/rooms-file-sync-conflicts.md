# Разрешение локальных конфликтов

18 октября 2026 года. Продолжение [истории и кеша](rooms-file-sync-history.md).

## Как пользоваться

В настройках комнаты открыть синхронизацию → «Состояние файлов». У получателя с локальными правками появляются «Разобрать конфликт» и «Отложить». В окне разбора показаны относительный путь, размер и дата изменения локального файла, размер и дата публикации общей ревизии, её короткий ID.

* **Принять общую версию** заменяет только выбранный файл. Его прежние байты сохраняются в `.havvn-sync/transactions/op-*/previous` рабочей папки. Новая общая ревизия не создаётся: получатель применяет уже подписанную версию издателя.
* **Сохранить обе** сначала создаёт отдельную проверенную копию локальных правок в `.havvn-local/copy-<случайный ID>/<имя файла>`, затем принимает общую версию с обычной резервной копией. Относительный путь отдельной копии показан до подтверждения и после успеха. Каталог `.havvn-local` исключён из публикации и сетевых путей, а также из очистки приватного кеша версий. Если создание отдельной копии не удалось, основной файл не заменяется.
* **Отложить** сохраняет в защищённом локальном индексе паузу выбранного документа. Пауза действует и на последующие общие версии этого документа, переживает перезапуск и не останавливает другие файлы. Строка продолжает показывать ожидающее обновление. Открыть разбор можно позднее; принятие версии снимает паузу. Повторный выбор прежнего пути не снимает паузу; новая привязка её сбрасывает.

При принятии состояние общего переключателя автоприменения не меняется. Если он включён, последующие версии принятого файла применяются автоматически до следующей независимой локальной правки. Если выключен, подтверждается только выбранное обновление.

## Сравнение текста

Построчный просмотр поддерживает строгий UTF-8, до 128 КиБ и 400 строк с каждой стороны. Различия строятся ограниченным LCS без новой зависимости. Удалённые локальные строки помечены минусом, новые общие — плюсом; неизменённый контекст и номера строк сохраняются. CR и BOM отображаются явно. React выводит содержимое как текст; HTML из файла не исполняется.

Для Office, PDF, архивов, изображений и других бинарных файлов, неподдерживаемой кодировки или превышения размера показываются сведения о версиях и объяснение отсутствия сравнения. Автоматическое объединение содержимого не выполняется.

## Проверки перед заменой

Все команды доступны только главному frame доверенного основного renderer. IPC проверяет UUID комнаты/корня/документа, токен предпросмотра и перечисление действий. Renderer не задаёт пути назначения, имена отдельных копий, контрольную сумму или ожидаемую голову.

Предпросмотр выдаёт одноразовый токен на пять минут. В main process сохраняются точная общая ревизия, политика, поколение и путь привязки, SHA-256 локального файла либо его отсутствие. Перед заменой повторно проверяются эти условия, отсутствие конфликтов путей и единственность головы. Изменение или удаление локального файла, новая общая ревизия, смена политики, перепривязка, закрытие/смена контекста комнаты требуют нового просмотра.

Общие байты копируются в приватный снимок и проверяются по подписанному описанию torrent/pieces. При E2E используется ключ нужной эпохи. Содержимое снова проверяется при подтверждении; автоматическое разрешение автоприменения не требуется для явно подтверждённого файла. Ссылки/junctions/hardlinks в локальных путях не разрешаются. Отдельная копия создаётся без перезаписи существующих файлов, проверяется по ожидаемому SHA-256 и синхронизируется на диск перед заменой основного файла.

Разбор сериализован с обычным применением и очисткой кеша. Файловая транзакция использует прежние проверки локального отпечатка, резервное сохранение и публикацию без перезаписи. После установки общей версии её отпечаток и снятие локальной паузы фиксируются вместе. При ошибке сохранения индекса после установки подписанный журнал позволяет восстановить применённый отпечаток. Сохранённая ранее пауза может остаться до повторного явного принятия; автоматическое возобновление при неопределённом результате не предполагается.

Ожидание torrent-метаданных совместно используется одновременными локальными операциями. Потерянный запрос повторяется раз в две секунды в пределах 15 секунд; таймеры закрываются при ответе, истечении ожидания или закрытии комнаты. После перезапуска адресные сообщения выбирают новый рабочий канал участника: старый канал может ещё сообщать `connected` до своего таймаута. Это проверяется настоящим переподключением, а не только восстановлением локального индекса.

Если редактирование прервало прежнее применение и оставило неоднозначный журнал этого же файла, явное подтверждение может завершить его как отменённое намерение. Перед этим проверяются подпись его ревизии, ID документа и точный текущий SHA-256. Файлы `previous`/`next` старой операции не удаляются. Новая транзакция отдельно сохраняет подтверждённый текущий файл. Неоднозначные журналы других файлов и неподтверждённые ревизии требуют отдельной проверки.

## Ограничения и проверки

Этот этап разрешает локальное расхождение получателя с одной общей головой. Несколько подписанных голов и совпадающие пути разных документов не выбираются автоматически. У таких строк нет действия принятия; остаётся объяснение необходимости отдельной проверки. Права издателя и получателя не меняются.

Тесты покрывают открытые/E2E-файлы, сохранение обеих копий, резервные копии, отсутствие новых публикаций от получателя, продолжение автоприменения, выключенный общий режим, перезапуск с отложенным файлом, обновления других файлов, одноразовость токена, смену файла/головы/привязки, повреждённый кеш, существующее имя копии, неоднозначный журнал после поздней записи редактора, миграцию пауз, недоверенные IPC-запросы и ограничения текстового сравнения.

Нативный сценарий `npm run test:room-sync-ui` использует два настоящих Electron-профиля, DPAPI, E2E WebRTC и реальный React/preload/IPC. Он откладывает конфликт, получает новую голову, перезапускает получателя, сравнивает версии, сохраняет обе копии, затем принимает следующую общую версию с резервной копией и проверяет возобновление обновлений. Снимки окна сравнения сохраняются в `dist/room-sync-ui/evidence/resolve-wide.png` и `resolve-narrow.png`.

Итог проверки: 3293 теста Vitest в 246 наборах прошли при `npx vitest run --maxWorkers=2`, отдельно прошли все 8 проверок Node из стандартного `npm test`. Полный нативный сценарий истории/кеша/восстановления/конфликтов прошёл; широкие и узкие снимки сравнения просмотрены. Typecheck всех трёх частей, полная сборка и ESLint изменённых модулей прошли. Сборка renderer сохраняет три прежних предупреждения о размере bundle. Проверка реальными Office/IDE на физических ПК остаётся отдельной приёмкой.
