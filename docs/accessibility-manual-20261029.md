# Ручная проверка озвучивания — 29 октября 2026

Источник результата — ответы пользователя в чате после проверки Havvn на одном
домашнем ПК. Использован **«Экранный диктор» Windows**; версия скринридера и
Windows не сообщены. На предоставленном скриншоте интерфейс русский; язык
синтезатора отдельно не указан.

## Ответы пользователя

1. Навигация клавишей Tab: «Навигация работает исправно».
2. Палитра команд, стрелки, Escape и возврат фокуса: «Работает».
3. Названия и значения полей, списков и переключателей: «Да».
4. Выбор разделов переноса настроек и отмена: «Работает», с замечанием о
   геометрии выделения группы на скриншоте.
5. Ошибка невалидного приглашения: «Вроде работает» — предварительное
   подтверждение, без уточнения фактически произнесённого текста.
6. Вложенные диалоги и удержание фокуса: «Работает».
7. Озвучивание статусов и уведомлений: «да».

Функциональные шаги подтверждены пользователем с указанной оговоркой по пункту
5. Это ручная проверка одного скринридера, а не сертификат совместимости со
всеми средствами доступности. Физическое переключение контрастной темы Windows
и проверка нескольких устройств этим ответом не подтверждены.

## Замечание по выделению разделов переноса

На скриншоте верхняя граница прямоугольного выделения группы проходит через
текст «Разделы для переноса или восстановления». Поведение выбора разделов
пользователь подтвердил. Дефект воспроизведён в изолированном окне с настоящим
`SystemSection`: подсветка результата поиска (`data-settings-search-target`)
рисовалась через нативный `legend`.

Исправление сохраняет `fieldset`/`legend`, доступное имя группы и нативную
блокировку элементов во время переноса. Заголовок размещён внутри окрашиваемой
области, а содержимому добавлены отступы. Автоматическая проверка контролирует
геометрию заголовка на широкой и узкой панели, имя группы и семь checkbox в
дереве доступности Chromium, выбор пробелом и блокировку во время операции.
Снимки: `dist/settings-transfer-ui/sections-highlight.png` и
`dist/settings-transfer-ui/sections-highlight-narrow.png`.

Пользовательская повторная проверка исправленной сборки ещё не получена.

## Автоматическая проверка исправления

`node scripts/smoke-settings-transfer-ui.cjs` прошёл все 15 групп проверок.
Снимки широкой и узкой подсветки просмотрены: линия не пересекает заголовок.
Сборка Electron в составе `npm run test:accessibility` прошла.

Общий `smoke-accessibility.cjs` остановился на более раннем сценарии входа в
комнату: ожидался фокус `.rooms-input-code`, фактически фокус находился на поле
ника с `autocomplete="nickname"`. Этот сценарий не использует исправленный
блок разделов переноса. Общий прогон не считается пройденным; его ошибка не
отменяет сообщённые пользователем результаты ручного прослушивания.

## Дополнение: лишние рамки внутри поиска

По второму скриншоту пользователя убраны дополнительные обводки и тени
внутренних полей: поиск торрентов, загрузок, RSS, файлов и чата комнаты,
компактный поиск торрентов, поиск настроек, числовые поля настроек, консоль,
палитра команд и общие поля `Input`. Активное поле отмечается цветом его
границы либо границы контейнера. Контуры кнопок и системная обводка
`forced-colors` сохранены.

`node scripts/smoke-themed-controls.cjs` прошёл: проверены настоящее поле
поиска, 11 вариантов полей без внутренней рамки, системная контрастная
обводка и видимый фокус кнопки при Tab. Снимок поиска просмотрен.

Исторические автоматические квитанции от 27 октября не переписываются этой
записью, и общий релизный статус не повышается. Исходный сценарий находится в
[отчёте приёмки одного ПК](pc-acceptance-20261027.md#ручное-прослушивание-скринридером).
