# FUN-02. Локальная медиатека

Обновлено 26 октября 2026 года. Медиатека расширяет прежнюю страницу истории
просмотра и сохраняет её идентификатор навигации `watch-history`.

## Возможности

- «Продолжить» — незавершённые записи с сохранённой позицией для возобновления;
- «Смотрю» — начатые, но не завершённые записи, включая просмотр с начала;
- «Завершено» — завершённые или вручную отмеченные записи;
- «Все медиа» — также ещё не открывавшиеся видео и аудио из известных загрузок.

Есть поиск по названию и пути, группировка известных сезонов и числовой порядок
серий. Автоматически распознаётся один явный маркер `SxxExxx`. Диапазоны,
несколько серий в одном файле и неясные имена не превращаются в угаданную серию.
Пользователь может исправить тип, название, сезон и серию; номера необязательны.
Числовые поля используют обычный текстовый ввод без системных стрелок.
Группы ограничены идентичностью торрента: одноимённые выпуски автоматически
не объединяются. Внешние постеры, каталоги и сетевые метаданные не запрашиваются.

## Идентичность и сохранность

Карточка использует существующий ключ истории: хеш торрента и относительный
путь из его метаданных. Название загрузки, абсолютная папка сохранения,
новый локальный ID после повторного добавления и порядок массива файлов
не являются идентичностью. Фактический индекс файла разрешается заново по пути.
Если хеш ещё неизвестен, остаётся прежняя привязка истории к локальному ID;
сопоставление разных источников по похожим именам не выполняется.

Перенос в новую известную папку сохранения проверен настоящим чтением HTTP Range.
Произвольное внешнее переименование файла без обновления данных загрузки не
угадывается: отсутствующий путь остаётся недоступным. Другой торрент с тем же
именем или файл с повторяющимся basename не получает чужую позицию.

Классификация хранится отдельно от позиции в `havvn.mediaLibrary.v1`.
Исправление карточки не переименовывает файл и не меняет историю.
Очистка истории удаляет позиции и статусы просмотра, сохраняя медиатеку
и ручные данные. Прежние session/revision-ограничения встроенного и внешнего
плеера остаются действующими: запоздалый старый плеер не восстанавливает
удалённую запись и не перезаписывает новую позицию.

## Доступность

Карточки различают готовый локальный файл, загрузку, остановленный источник,
отсутствующий файл/источник и ещё не подтверждённую доступность. Отсутствие
метаданных или истёкшее наблюдение не выдаются за готовность. Проверка обычного
индекса не возобновляет загрузки. Перед открытием снова читаются текущая
загрузка и файлы; используется существующий встроенный или внешний плеер.
При неизвестной доступности можно явно выбрать «Проверить и открыть».

**Исправлен случай старого кеша после повторного добавления.** Сохранённые
счётчики скачанных байтов больше не подтверждают готовность. Кеш даёт только
описание файлов; нужны актуальные file stats либо завершение текущей загрузки
с учётом выбранных файлов. Даже файл полного размера может быть лишь
предварительно выделенным местом. Без актуального подтверждения он не становится
готовым. Проверка размера и состояния загрузки не заменяет полную проверку хеша.

## Границы индекса

Индекс ограничен 500 карточками и 1 МиБ сериализованных данных в UTF-16.
За проход рассматриваются до 50 источников, одновременно идут до трёх
запросов. Первыми проверяются источники из истории. Для остальных есть
«Проверить следующие источники»; ограничение видно в интерфейсе.
На источник main возвращает ограниченную порцию медиа, сохраняя исходные
индексы. Проверка диска выполняется после фильтрации и ограничения порции.
Файловая система целиком не сканируется; исходные torrent-метаданные читает
существующий API движка.

Повторные проверки выполняются раз в десять секунд, пока страница видима.
Смена состава/состояния загрузок из общего download-state запускает проверку
заново. Наблюдения доступности старше двадцати секунд не считаются актуальными.
Закрытие страницы останавливает последующие запросы текущего прохода.
Неизменённый индекс не записывается при каждом обновлении доступности.

При переполнении предпочтение отдаётся ручным данным и истории, затем более
свежим карточкам. История по-прежнему имеет собственный предел в 200 записей.
Повреждённый, будущий формат и ошибка хранилища показывают предупреждение;
такие данные не заменяются пустым индексом. Ошибка сохранения оставляет редактор
открытым. Индекс локальный для профиля, его перенос между ПК не добавлен.

## Проверки

Прошли 97 тестов в 11 файлах: ключи, повторное добавление, смена папки,
разные торренты и одинаковые basenames, неоднозначные серии, ручные данные,
границы индекса, ошибки хранилища, ограничение запросов, отмена прохода,
внешний плеер и прежние защиты истории. Отдельно проверены настоящий перенос
файла с HTTP Range и файл полного размера без актуального подтверждения загрузки.

Настоящий Electron-сценарий завершил 13 групп проверок: миграция позиций,
возобновление и дорожки, внешний плеер, отдельное окно, перезапуск renderer,
новый ID и перестановка индексов, ручные название/сезон/серия, сохранность
позиции, четыре раздела и поиск, исчезновение файла и источника, очистка истории
без потери классификации, размещение при 1050/440 px. Использованы созданные
для теста видео, FFmpeg и изолированный профиль. Число запусков торрент-передачи
в сценарии — ноль. Снимки: `artifacts/fun02/ui/`.

Проверены типы и production-сборка main/renderer/guest. ESLint затронутого
ядра медиатеки завершился без ошибок и предупреждений. JSON с хешами исходников,
сборки и журналов: `docs/media-library-acceptance.json`.

```powershell
npm run test:media-library
npm run typecheck
npm run build
npm run test:media-library-ui
```

Приёмка относится к одному Windows-ПК и двум текущим контрактам плеера.
Она не заменяет установочную и внешнюю приёмку нового кандидата по FUN-01.
