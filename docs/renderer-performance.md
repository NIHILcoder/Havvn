# Общее состояние загрузок и замеры интерфейса

Этапы 6 и 7 плана оптимизации, 10 октября 2026.

## Изменения

`renderer/state/download-state.ts` хранит один список загрузок, индексы записей и статистики по ID, счётчики и агрегаты. Одинаковые записи, статистика и агрегаты сохраняют ссылки между IPC-снимками. Обработка статистики линейна по количеству задач; повторный `find` для каждой загрузки удалён. Массив записей копируется только при изменении статуса или пересечении границы завершения.

App, DownloadsPage, SearchPage и индикатор буфера плеера используют одну подписку `onDownloadStats` и один таймер обновления метаданных. Подписка освобождается после последнего владельца. Параллельные запросы списка объединяются. Новый push выигрывает у более старого ответа; локальные добавление/удаление инвалидируют запрос, начатый до изменения. Статистика удалённых задач освобождается, неизвестные ID не вызывают частые повторные чтения.

App больше не подписан на статистику загрузок. Боковая панель получает счётчики, строка состояния — скорости/активность/пиров, строка загрузки — свою запись и статистику. Подзаголовок списка подписан на отображаемый ratio. Сортировки по скорости/прогрессу остаются живыми; сортировки по имени/дате не зависят от тиков. Состояние сохраняется при переходе между страницами. Настройки, IPC API и формат данных main не изменены.

## Воспроизведение замеров

После установки зависимостей:

```powershell
node scripts/performance-renderer.cjs current artifacts/performance/current.json
```

Контроль для этого изменения берёт **только пять файлов renderer** из HEAD, остальные файлы рабочего дерева общие для обоих вариантов:

```powershell
node scripts/performance-renderer.cjs before-1 artifacts/performance/before-1.json --ui-from-head
node scripts/performance-renderer.cjs after-1 artifacts/performance/after-1.json
# Повторить с суффиксами 2 и 3, последовательно.
node scripts/summarize-renderer-performance.cjs
```

После коммита этого этапа HEAD уже не является прежней версией. Каждый JSON содержит SHA-256 исходников, время, Electron и параметры компьютера; сравнение проверяет неизменность исходников внутри серии. Во время измерений не запускать сборку, тесты и другие нагрузки.

## Методика и границы

Настоящие App, страницы, строки и StreamPlayerModal собраны webpack с production React profiling. API заменён синтетическими ответами: 1000 загрузок, один меняющийся торрент на каждом тике, комната с 1000 файлами и 200 сообщениями, воспроизведение настоящего WebM 320×180/15 fps. Внешняя сеть заблокирована. Профиль и bundle создаются во временной папке и удаляются родительским процессом после выхода Electron.

Четыре сценария: список загрузок; открытая комната при одних обновлениях статистики торрентов; комната с обновлениями прогресса файлов; видео поверх загрузок. Каждый сценарий после прогрева содержит 16 выборок с интервалом 750 мс. Три запуска каждого варианта используют свежие процессы и профили. CPU-счётчики инициализируются перед сценарием. Сохраняются private bytes и working set каждой роли Electron, V8 heap renderer, Node memory main, CPU, вызовы компонентов, длительности React commit и callback статистики, отклонения таймеров main/renderer.

Сводка — медиана трёх значений, вычисленных отдельно для каждого запуска. Для CPU используется среднее внутри запуска, затем медиана трёх средних. p95 — nearest rank внутри каждого запуска, затем медиана трёх p95. `React commit` содержит все обновления поддерева, включая события видео и комнат; это не время только одного stats callback. Отклонение таймера — показатель задержки его исполнения, не задержка сети.

Окно скрыто, GPU программный, React с профилированием. Замер характеризует стоимость UI при контролируемых данных. Он не измеряет реальный swarm, скрытый room-engine, голоса, native daemon, FFmpeg или полное потребление Havvn в рабочей сети. Private bytes, working set и V8 heap различаются; сумма working set может повторно учитывать общие страницы. Снижение CPU/рендеров не доказывает снижение ОЗУ. Принудительный GC не применяется.

## Проверки

Unit-тесты проверяют стабильность записей, счётчики и байты, совместную подписку и освобождение таймера, объединение запросов, гонки push/pull и удаления, завершение/перепроверку, ошибки и новые метаданные. Electron-замер также проверяет живую сортировку по скорости, фильтр паузы, восстановление состояния при переходах, фактическое воспроизведение и удаление video при закрытии. Отдельный smoke проверяет буферизацию, ошибки декодирования, перемотку и episode-prefetch.

Итоговая проверка: `npm test` — 222 файла / 2994 теста Vitest и 8 тестов Node; `npm run typecheck` — Electron, renderer, guest; полная сборка и повторная сборка renderer после финального изменения store; ESLint всех изменённых файлов этого этапа; `smoke-player-buffer.cjs`; шесть последовательных запусков профилирования и проверки их исходников. Все проверки прошли. Сборка renderer сохраняет три прежних предупреждения webpack о размере ресурсов/runtime chunk. Canvas проходит проверку TypeScript.

Сырые измерения и сводка сохраняются в `artifacts/performance/`. Численные результаты этой серии добавлены ниже.

## Результаты серии 10 октября 2026

Electron 44.4.2, Windows, Ryzen 5 3600, 12 логических CPU, около 16 ГиБ RAM. Контроль и текущая версия запускались последовательно, три раза каждый, без параллельных сборок/тестов. Предварительные `before.json`/`after.json` и промежуточный прогон с параллельными тестами в итоговую сводку не входят.

- **1000 загрузок:** вызовы App/DownloadsPage 18 → 1, видимых строк 306 → 16; p95 React 9,0 → 1,0 мс; средний суммарный CPU Electron 0,272 → 0,171% (−37%). Медиана private bytes renderer 79,50 → 76,66 МиБ; диапазоны медиан запусков 74,30–81,69 и 75,88–76,77 МиБ пересекаются.
- **Комната при обновлении только torrent stats:** вызовы App/RoomsPage 18 → 1. Оставшийся вызов происходит из-за планового обновления сводки комнат; статистика торрентов обновляет строку состояния отдельно. Средний CPU 0,234 → 0,083% (−65%). Private bytes 120,36 → 109,59 МиБ. p95 React 10,2 → 7,5 мс включает плановое обновление самой комнаты; этот показатель не означает, что статистика по-прежнему рендерит комнату.
- **Комната с обновлениями прогресса:** RoomsPage 18 → 17, p95 React 12,3 → 6,7 мс, CPU 0,367 → 0,342%, private bytes 122,84 → 109,48 МиБ. Обновления комнаты продолжают вызывать её отображение.
- **Видео поверх 1000 загрузок:** подписки статистики 3 → 1, вызовы строк 306 → 16, p95 React 6,1 → 0,4 мс, CPU 0,467 → 0,400%. Private bytes 108,38 → 104,48 МиБ, диапазоны 102,43–108,48 и 104,40–105,01 МиБ пересекаются.

Во всех сценариях p95 отклонения таймера renderer около 0,8–1,0 мс; улучшения этого показателя серия не демонстрирует. Синхронный stats callback после переноса работы в store занимает несколько десятых миллисекунды и может быть дольше прежнего callback: раньше часть работы выполнялась отложенными React state-updater во время рендера. Его следует рассматривать вместе с временем React и CPU.

Тест показывает сокращение работы UI и более низкие медианы памяти renderer в этой серии. Разброс, порядок сценариев, GC и программный GPU ограничивают выводы о памяти; полная ОЗУ Havvn при настоящих загрузках/RTC/транскодировании не измерена. Нельзя переносить полученные проценты на сетевую нагрузку или складывать их с расчётными бюджетами кешей предыдущих этапов.
