# Обновления комнат и локальное хранение

Движок комнаты передаёт по настольному IPC полный снимок один раз, затем только
изменения. Основной процесс восстанавливает `RoomState` для внутренних подписчиков,
а в окно интерфейса также отправляет изменения. Preload собирает их в привычный
`RoomState`: API `onRoomUpdate` и протокол обмена с участниками комнаты сохраняются.

Файлы, участники, папки, чат, события и зеркала серверов сопоставляются по ID.
Изменение одного поля не требует повторной передачи остальных элементов.
Удаления, перестановки и исчезновение необязательных полей передаются явно.
Каждый поток имеет идентификатор и последовательный номер. При пропуске пакета,
перезагрузке интерфейса или новом движке запрашивается полный снимок. Снимок
восстановления передаётся событием, чтобы последующие изменения сохранили порядок.
Базовые состояния освобождаются при выходе, сбое движка, остановке приложения и
приостановке сети. Серии срочных обновлений объединяются с интервалом до 50 мс;
обычные обновления сохраняют прежний интервал 700 мс. Действия с голосом, сетью
и записью сообщений выполняются сразу, независимо от обновления интерфейса.

`rooms.json` читается через кэш защищённых данных. Если размер файла не превышает
8 МиБ, разобранный JSON сохраняется между запросами. Изменение размера, времени
или идентификатора файла сбрасывает кэш; ошибка записи также его сбрасывает.
Для больших архивов один разбор разделяется только внутри синхронной операции
и освобождается после неё. Геттеры копируют запрошенную комнату или раздел,
поэтому изменение возвращённого объекта и неудачная запись не повреждают кэш.
Порог 8 МиБ относится к размеру JSON на диске, а не к объёму объектов в ОЗУ.

Проверка источника события использует наличие записи комнаты без расшифровки
всех приглашений. Чтение одной комнаты открывает только её защищённую запись.
Счётчик непрочитанных использует время получения и автора сообщения; текст
для него не расшифровывается. Повторно показанный текст хранится в LRU с бюджетом
1 МиБ для строк UTF-16 и максимумом 4096 записей. Бюджет строк не включает
служебные объекты Map. Неудачная расшифровка не кэшируется. Недоступность системного
шифрования, очистка сообщений, изменение срока хранения и удаление просроченной
истории сбрасывают этот кэш.

Поступление сообщения шифрует только новый или обновлённый текст; прежние
шифрованные тела сохраняются. Локальное сообщение и квитанция повторной отправки
по-прежнему записываются атомарно перед отправкой участникам. Очистка всех разделов
одной комнаты выполняется одной атомарной записью. Формат сохранённых данных
совместим с существующими профилями, импортом, миграцией и восстановлением.

Проверка:

```sh
npm test
npm run typecheck
npm run build
node scripts/smoke-room-state-storage.cjs
```

Smoke использует настоящий Electron, preload с `sandbox: true`, системное
шифрование, временный профиль и loopback-трекер. Проверяются 1000 синтетических
файлов и 200 сообщений, перезагрузка интерфейса, восстановление движка, замена
JSON вне приложения и выход из комнаты. Родительский процесс удаляет профиль
после завершения Electron и ограничивает длительность сценария.

В проверке от 10 октября 2026 года JSON-представление полного состояния занимало
527432 байта, а изменения прогресса и лимита скорости — 346 байт. Десять запросов
списка комнат не вызвали чтений `rooms.json`. Эти числа характеризуют конкретные
тестовые данные и JSON-представление пакетов; фактический формат IPC имеет свои
накладные расходы. Полные снимки при первом подключении, восстановлении и
ответах на отдельные команды остаются необходимыми. Сборка состояния и сравнение
списков всё ещё проходят по данным комнаты, а публичные вызовы через contextBridge
могут копировать объекты. Изменение общего потребления ОЗУ и CPU следует измерять
отдельно на одинаковой рабочей нагрузке.
