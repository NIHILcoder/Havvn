# Кеши кусков и освобождение движков

Передача изменений комнат и кэши локального хранилища описаны отдельно в
[room-state-storage.md](room-state-storage.md).

В настольном приложении кеш прочитанных кусков WebTorrent ограничен байтами.
Classic использует общий бюджет 32 МиБ для всех загрузок и раздач; движок
комнат — 16 МиБ для всех комнат; ссылки-раздачи — 8 МиБ для всех опубликованных
файлов. Таким образом, суммарный потолок этих кешей — 56 МиБ. Бюджеты заданы
в `electron/torrent/piece-cache.ts` и не умножаются на количество торрентов.

Встроенный `storeCacheSlots` отключён, чтобы второй независимый кеш не хранил
ещё 20 кусков каждого торрента. При исчерпании общего бюджета удаляется давно
не использовавшийся кусок. Куски крупнее бюджета читаются из хранилища по
запрошенному диапазону без кеширования. Одновременные чтения одного куска
объединяются. Запись инвалидирует старый кеш; закрытие хранилища освобождает
все его записи. Кеш не удерживает большой исходный ArrayBuffer ради маленького
среза. Хеширование при создании торрента и получение его метаданных обходятся
без постоянного кеша прочитанных кусков.

Это потолок сохранённых в кеше байтов, а не всей ОЗУ приложения. Незавершённые
чтения и записи, сборка кусков, сетевые буферы, Chromium и кеш ОС учитываются
отдельно. Частое вытеснение может увеличивать чтение с диска при раздаче многих
крупных файлов. Проверка хешей, хранение файлов на диске и ограничения комнат
на запись сохраняются. Native Transmission использует собственный кеш и
данным бюджетом не регулируется.

Окна instant-share и remote-cast создаются при публикации. Пустые `list`, `get`
и `stop` не запускают окно. Через пять секунд после остановки последней
раздачи/сессии окно закрывается; новая публикация создаёт его снова.
UI-запросы `list`/`get` не продлевают период простоя. Ожидание
подключения зрителя остаётся активной сессией: отсутствие пиров не закрывает
действующую ссылку. Незавершённые команды, включая долгое хеширование, также
удерживают окно. При сбое загрузки или закрытии окна ожидающие команды
отклоняются, таймеры очищаются; IPC принимается только от основного фрейма
текущего окна.

Пустой клиент ссылок-раздач уничтожается сразу после освобождения последнего
торрента и завершения хеширования. Пустой файловый клиент комнаты уничтожается
через пять секунд; сама комната, чат, голос и rendezvous остаются активными.
Хеширование, шифрование, проверка файлов и подготовка воспроизведения удерживают
клиент до завершения операции. Наличие торрента, включая активную раздачу без
пиров, предотвращает уничтожение. Выход из комнаты и VPN kill-switch по-прежнему
немедленно останавливают её сетевые ресурсы. Освобождение не удаляет исходные
или скачанные файлы.

Для проверки:

```sh
npm test
npm run typecheck
npm run build:electron
node scripts/smoke-sharing-idle.cjs
```

Тесты включают общий бюджет нескольких хранилищ, гонки чтения с записью и
закрытием, реальную передачу по loopback через WebTorrent и сценарии повторной
публикации. Smoke запускает настоящий Electron с отдельным временным профилем
и loopback-трекерами: проверяет завершение процесса окна раздачи, повторную
раздачу, закрытие remote-cast, освобождение пустого клиента комнаты и сохранение
активной раздачи. Временный профиль удаляет родительский процесс после выхода
Electron, когда Chromium освобождает файловые блокировки.

Smoke печатает PID и private memory процессов renderer в КиБ. GPU в нём отключён:
проверяется жизненный цикл процессов, а не скорость видео или экономия ОЗУ под
реальной нагрузкой. Для оценки производительности под нагрузкой необходимы
отдельные замеры на одинаковых торрентах и сценариях до и после изменений.
