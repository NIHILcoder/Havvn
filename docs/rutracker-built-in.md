# Встроенный RuTracker — 28 октября 2026

## Как подключить

В Havvn открой **Поиск → Провайдеры → RuTracker → Подключить и войти**. Источник сохраняется, затем открывается отдельное окно входа. Войди самостоятельно и закрой окно: Havvn проверит доступ. Установка Python, выбор `.py` и ручное копирование cookie для этого источника не требуются.

При проблемах открой настройки подключения под источником: там остались системное/прямое подключение, HTTP/SOCKS5 и зеркала. Для зеркал RuTracker можно указать HTTPS-домен или адрес с `/forum`. Неверный вход и капча не вызывают повторов по всем зеркалам. Проверку сайта пользователь проходит сам.

Другие источники, включая пользовательские Python-плагины, доступны в раскрывающемся разделе. Уже настроенные плагины не удаляются и не заменяются автоматически. Если старый RuTracker-плагин больше не нужен, его можно отключить обычным переключателем.

## Что изменилось

- 29 октября добавлена [карточка раздачи](search-release-preview.md): описание, обложка, скриншоты и просмотр с увеличением. Открывается нажатием на название в основном и быстром поиске; сведения загружаются при открытии карточки.
- Новый тип `rutracker` работает внутри основного процесса на TypeScript. Он использует существующий браузерный транспорт, изолированную сессию источника и выбранный маршрут подключения.
- Поиск читает только страницу выдачи: названия, размеры, число сидов/личеров и идентификаторы тем. Предварительное открытие двадцати тем ради magnet удалено из встроенного пути. Разбор учитывает Windows-1251 в запросе и UTF-8 из браузерного документа.
- «Показать ещё» получает следующую страницу только выбранного источника, сохраняя уже показанные результаты. Курсор хранит основной процесс; интерфейс не передаёт произвольные URL страниц. Курсоры ограничены по количеству и времени жизни, сбрасываются при изменении подключений.
- Тема открывается при выборе раздачи или её предпросмотра. Magnet кэшируется для повторного выбора. При отсутствии magnet файл `.torrent` получается через ту же сессию и проверяется перед передачей движку. Страница входа не принимается за торрент.
- У неразрешённых тем есть стабильная идентичность источника/темы. Похожие названия и размеры не выдают разные темы за один торрент. Повторная страница обновляет существующую строку.
- При истечении сессии в статусе источника появляется «Войти на сайт»; успешный вход повторяет только этот источник. Старые ссылки результатов сбрасываются при выходе/изменении настроек.
- Основной и компактный поиск сохраняют быстрые сообщения кэша, пришедшие до ответа `search:start`, и игнорируют ответ уже отменённого/заменённого запуска. Компактное окно также использует разрешение защищённого источника перед добавлением.

## Проверки

204 теста Vitest в 17 файлах прошли без пропусков: парсер RuTracker, отложенное получение ссылок, пагинация/кэш, зеркала, ошибки входа и капчи, отмена, защищённая загрузка `.torrent`, история и прежние сетевые источники. Сетевые проверки выполнены на локальных серверах вне песочницы; её ограничения не подменялись пропуском тестов. В существующем тесте таймаута зеркала зафиксированы часы, чтобы погрешность в 1 мс не давала случайного падения.

Дополнительно прошли 19 существующих Python-тестов старого RuTracker-плагина.

Сценарий `node scripts/smoke-rutracker-ui.cjs` прошёл в настоящем скрытом окне Electron с отдельным профилем и подставным API: подключение без обращения к Python, ранний ответ кэша, сохранение первой страницы при подгрузке, получение ссылки только при скачивании, кнопка входа/повтор источника и компактное окно добавления. Проверена раскладка 1120 и 560 px.

## Границы

По запросу пользователя 28 октября выполнена живая проверка через настоящий браузерный транспорт Havvn с существующей сессией настроенного Python-источника и системным подключением. На `rutracker.org` и `rutracker.net` страница входа и поиск `ubuntu` вернули HTTP 403 с проверкой Cloudflare. Транспорт корректно вернул `captcha`; выдача, пагинация и получение magnet на настоящем сайте остаются непроверенными. Пароли и cookie не извлекались, формы входа не отправлялись, торренты не скачивались, настройки источника не изменялись. Отчёт: [живая проверка](../artifacts/rutracker-live-20261028/report.json). Повторяемый сценарий: `node scripts/probe-rutracker-live.cjs <абсолютный путь профиля Havvn>`; приложение должно быть закрыто.

Для продолжения потребуется пройти проверку сайта в окне подключения. Встроенный источник имеет отдельную сессию от старого Python-источника; текущая проверка не означает, что в него уже выполнен вход. Автоматическое решение капчи не реализуется.
