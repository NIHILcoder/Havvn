# Перенос и восстановление настроек

23 октября 2026 года. PER-06 из [плана реализации](havvn-implementation-plan.md).

## Актуальное поведение

В «Настройки → Система → Резервная копия» можно выбрать разделы для экспорта, импорта и возврата к состоянию до последнего импорта:

- Настройки приложения.
- Категории.
- Расписание.
- Приватность.
- Темы и оформление: библиотека и активная тема, встроенные шрифты, стекло, фон, профили оформления, акцент и шрифт интерфейса.
- Горячие клавиши.
- Панели, интерфейс и виды загрузок: размеры боковых панелей комнаты, масштаб, плотность, уменьшение движения, стартовая страница, единицы скорости, язык и [сохранённые виды загрузок](download-views.md).

Ни один раздел не выбран — кнопки переноса отключены. Изменения формы нужно сохранить или отменить, редактор темы — закрыть. Это предотвращает перезапись несохранённого черновика. Во время операции элементы выбора и повторные действия недоступны.

Файлы нового экспорта используют `version: 2` с явным списком разделов. Остальные значения не попадают в файл. При импорте применяется пересечение выбора пользователя и разделов файла: файл только с хоткеями не сбрасывает тему. Старые файлы v1 по-прежнему читаются и не меняют интерфейс. Неизвестные версии отклоняются.

Ключ `havvn.download-views.v1` добавлен к разрешённым предпочтениям раздела интерфейса. Старые файлы v2 и журналы восстановления без него поддерживаются и оставляют текущие виды на месте; явный `null` нового полного снимка очищает каталог. Разные каталоги видов проверены при переносе, частичном импорте, возврате и перезапуске.

Импорт показывает состав и изменения категорий перед подтверждением. Для применения всех настроек, включая уже открытые панели и фоновые службы, нужен перезапуск Havvn.

## Журнал операции и восстановление

Основные настройки и хранилище окна не имеют общей атомарной записи. Перенос выполняется с журналом:

1. До записи сохраняются прежние основные настройки и выбранные ключи интерфейса.
2. Основная конфигурация записывается вместе с настройками системного материала окна.
3. Preload записывает новые предпочтения окна и проверяет результат чтением.
4. Main принимает подтверждение обоих хранилищ и завершает операцию. Только после этого пользователь получает результат об успехе.

При ошибке записи или подтверждения восстанавливается прежнее состояние. Если восстановление самого хранилища окна тоже не удалось, журнал остаётся доступным. После перезапуска основные настройки восстанавливаются до запуска служб, а preload — до загрузки интерфейса. Неподтверждённый перенос не считается успешным.

Если автоматическое восстановление не закончено, приложение показывает сообщение и действие в разделе «Система». Новые переносы блокируются. Повреждённый журнал не удаляется; при обнаружении более позднего изменения основной конфигурации автоматическое восстановление отказывается перезаписывать её. Такой конфликт требует разбора сохранённых снимков.

Журнал и копия последнего успешного импорта находятся в отдельном `settings-transfer.json`. Изображения и шрифты не увеличивают стоимость обычных записей `config.json`. Пароли прокси, TURN и токен удалённого управления не копируются ни в переносимый JSON, ни в новые записи журнала. При восстановлении остаются текущие локальные секреты.

## Возврат после успешного импорта

«Восстановить прежние настройки» возвращает выбранные разделы к состоянию до последнего успешного импорта, с отдельным подтверждением. Более поздние изменения этих разделов заменяются. Разделы вне выбора сохраняются.

Новая, неизменённая категория, добавленная импортом, удаляется при восстановлении только при отсутствии назначений. Категории с назначениями в загрузках/RSS, отредактированные после импорта или созданные отдельно позже, сохраняются. Новое назначение, появившееся во время предпросмотра, останавливает устаревшее восстановление.

Копия одноуровневая: следующий успешный импорт заменяет её; успешное восстановление использует её без создания цепочки Undo/Redo. Ошибка или отмена восстановления не расходует копию.

## Ограничения формата

- Размер файла — до 32 МиБ, снимок интерфейса — до 16 МиБ.
- Библиотека — до 64 тем, профили оформления — до 8.
- Категории — до 2000, расписание — до 1000 записей.
- Принимаются проверенные встроенные растровые фоны, шрифты и токены тем. Произвольный CSS и внешние URL фонов не принимаются.
- Переносятся только перечисленные ключи интерфейса. История, данные поиска, учётные данные, идентичность комнаты и остальные значения localStorage сюда не входят.
- Предпросмотр основных настроек пока показывает состав разделов и число полей; подробное сравнение каждого значения можно развивать отдельно. Системное окно подтверждения в автоматическом прогоне получает подставленные ответы.

## Проверки второго этапа

```powershell
npm run test:settings-transfer
npm run test:settings-transfer-integration
npm run test:settings-transfer-ui
```

Интеграция использует sandbox, production preload и настоящий IPC. На двух профилях проверяются фон, библиотека со встроенным WOFF2-шрифтом, профиль оформления, хоткеи и размеры панелей, выборочный импорт/экспорт, восстановление и сохранность назначений категорий. Процесс принудительно завершается до подтверждения переноса, затем ещё два запуска проверяют восстановление и его устойчивость.

UI-проверка использует настоящие SettingsProvider и SystemSection с изолированным API. Проверяет выбор с клавиатуры, пустой выбор, блокировку во время операции, доступность восстановления, защиту формы и редактора темы, повтор восстановления и ширину 520 px. Снимки: `dist/settings-transfer-ui/wide.png`, `narrow.png`.

## Первый этап: история реализации

### Поведение

«Настройки → Система → Экспорт / импорт» переносит настройки приложения, категории, расписание и параметры приватности. Формат остаётся `version: 1`, чтобы читать ранее созданные файлы. Неподдерживаемая версия и некорректные известные поля отклоняются до записи; неизвестные поля не применяются.

Импорт сначала показывает состав файла и изменения категорий. Для категории видны имя, ID, иконка и цвет до/после; в системном окне отображаются первые 20 изменений и число оставшихся. Можно отменить импорт, не меняя профиль.

Правила объединения категорий:

- Новый ID добавляется вместе с исходным именем, иконкой и цветом.
- Совпадающий ID обновляет существующую категорию после подтверждения предпросмотра.
- Одинаковые имена с разными ID остаются разными категориями.
- Категории, которых нет в импортируемом файле, сохраняются. Пустой список не очищает существующие категории.
- Повторяющиеся ID внутри файла отклоняются.
- Назначения категорий существующим загрузкам и RSS не переписываются; их ID остаются действующими.

Открытые списки и поля выбора получают обновление категорий через `categories:changed`. Один источник состояния на окно объединяет запросы всех потребителей; старый ответ, пришедший после нового импорта, не возвращает прежние названия.

После импорта нужен перезапуск Havvn для применения всех параметров движка и фоновых служб. Сам импорт их не перезапускает.

### Запись и границы переноса

Все четыре переносимых раздела находятся в `config.json` и записываются одним вызовом electron-store. Неверный файл, отмена и проверенный отказ записи не оставляют последовательно применённые части импорта. Перед записью снимок сравнивается с тем, что пользователь видел в предпросмотре; при изменении настроек нужно повторно открыть файл.

Экспорт использует разрешённый список полей. `proxyPassword`, `customTurnCredential` и `webRemoteToken` не попадают в обычный JSON. При чтении старого файла эти поля также игнорируются, включая непустые значения; локальные секреты сохраняются в прежнем виде без расшифрования и повторного шифрования. Room identity и ключи комнат сюда не входят.

Файл ограничен 1 МиБ, категории — 2000, расписание — 1000 записей. Экспорт сначала записывает и синхронизирует временный файл в том же каталоге, затем заменяет выбранный файл. При проверенных ошибках прежний экспорт остаётся доступным.

Перенос renderer-предпочтений — оформления, хоткеев и расположения панелей — пока не добавлен. Выбор разделов, подробный предпросмотр остальных настроек и откат уже успешно завершённого импорта остаются следующей частью PER-06. Этот этап не заменяет отдельный защищённый экспорт комнат и не подтверждает поведение при отключении питания в момент записи.

### Проверки

```powershell
npm run test:settings-transfer
npm run test:settings-transfer-integration
```

Первый набор проверяет формат, категории, сохранение секретов, запись разделов одним вызовом, отказы, устаревший предпросмотр, доверенный IPC, отмену и обновление состояния категорий.

Интеграционный скрипт запускает настоящий Electron с двумя отдельными временными профилями. Используются production preload, IPC, electron-store и перезапуск принимающего профиля. Системные диалоги заменены предсказуемыми ответами; визуальная проверка самого окна подтверждения этим прогоном не выполняется. Рабочий Havvn, пользовательские профили, сеть, автозапуск и системные ассоциации не запускаются и не меняются.

В интеграции проверены:

- Экспорт из одного профиля и импорт в другой, включая кириллицу и конфликты категорий.
- Сохранение локальной категории с совпадающим именем, существующего назначения категории загрузке и геометрии окна.
- Сохранение локальных секретов и отсутствие их в переносимом JSON.
- Отмена предпросмотра и отказ при изменении настроек во время него.
- Настоящий отказ файловой системы, внедрённый на границе записи electron-store, с сохранением прежних разделов.
- Доставка сигнала через production preload и чтение новых категорий.
- Сохранение результата после полного завершения и нового запуска принимающего процесса.
