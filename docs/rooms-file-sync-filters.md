# Локальные исключения синхронизации

18 октября 2026 года. Продолжение [резервных копий](rooms-file-sync-backups.md) и [приёмки Windows](rooms-file-sync-acceptance.md).

## Как пользоваться

В синхронизации комнаты у подключённой папки открыть «Исключения папки». Ввести по одной маске в строке, нажать «Пересчитать исключения», проверить результат и выбрать «Сохранить и пересканировать». Пустой список оставляет только встроенные исключения. Изменённый текст без нового предпросмотра сохранить нельзя; отмена ничего не меняет.

Правила локальны для конкретного корня на этом устройстве, сохраняются в защищённом индексе и переживают перезапуск. Они не рассылаются участникам. При новой привязке папки или отключении список сбрасывается; повторное подтверждение того же пути сохраняет правила, но по-прежнему выключает автоматические режимы. Числовые лимиты истории/кеша независимы от исключений.

У издателя правила ограничивают публикацию. Если автопубликация включена, после сохранения запускается свежий обход; снятие маски может опубликовать ранее пропущенные файлы. У получателя правила ограничивают новые загрузки и применение; после снятия маски берётся текущая общая голова, если включено автоприменение и файл не отложен отдельно. Независимые локальные правки вызывают обычный конфликт. Выключенные автоматические режимы сами не включаются.

Рабочие файлы не удаляются, подписанная история не сокращается, уже опубликованные версии не отзываются. Сохранённые источники и начатая транспортная загрузка могут остаться в приватном кеше; его очистка управляется отдельно. Ручное восстановление и разрешение конфликта для исключённого пути также заблокированы до снятия правила. Восстановление ранее прерванных файловых транзакций продолжает сохранять старые байты.

## Синтаксис

- `*` — любое число символов внутри одного имени; `?` — один Unicode-символ.
- `**` отдельным компонентом — любое число уровней каталогов, включая ноль.
- Без `/` маска действует на имя на любой глубине: `*.log`, `cache`, `draft?.md`.
- С `/` маска начинается от корня: `cache/**`, `notes/private.md`, `src/**/generated/*.cs`.
- `**/cache/**` пропускает каталоги `cache` на любой глубине. Совпадение с каталогом исключает всё его поддерево.

Регистр не учитывается; сравнение использует NFC. Это ограниченный синтаксис масок, не регулярные выражения и не полный `.gitignore`. Нет отрицаний/включающих правил, комментариев, скобок, абсолютных путей, `..`, обратного слеша, завершающего `/` или `**` внутри имени. Для каталога следует писать `cache` либо `cache/**`. Максимум 64 уникальные маски, 256 символов на маску, 8192 суммарно и 16 компонентов пути. Пустые строки в редакторе игнорируются; дубликаты с учётом регистра/NFC отклоняются.

Правила дополняют прежние встроенные исключения: `.git`/другие служебные каталоги VCS/IDE, `node_modules`, сборочные каталоги, временные и lock-файлы, `.env`, известные имена и расширения ключей. Любой компонент `.havvn-*` исключён всегда. Путь с недопустимым именем, ссылка/junction, hardlink, неподдерживаемый тип или слишком большой файл не становится допустимым из-за маски.

## Предпросмотр и сохранение

Показаны включённые локальные файлы и пропущенные объекты с причиной: служебный каталог, встроенное правило, конкретная пользовательская маска, имя, ссылка, размер или тип. Отмечены пути, которые будут включены/исключены по сравнению с текущими правилами. Исключённые каталоги не обходятся, поэтому их строка и счётчик означают поддерево целиком, а не точное число файлов внутри.

Общий подписанный индекс показан отдельно, включая ещё не загруженные файлы. Один относительный путь может иметь локальную и общую строки с разными размерами. Результат выдаётся страницами по 100 строк; до 10000 посещённых объектов плюс 2000 общих документов. Ранее введённые пределы глубины, числа включённых файлов и размера сохраняются. Если обход не завершён, редактор остаётся доступен для исправления масок, но подтверждающий токен не выдаётся и частичный результат не показывается как полный. Например, можно исключить лишние файлы папки, выросшей за лимит 2000 файлов.

IPC принимает только корень, ограниченный список масок, UUID предпросмотра и номер страницы. Локальные пути из renderer не принимаются. Доступ имеет только главный frame доверенного окна. Одноразовый токен действует пять минут; новый просмотр того же корня отменяет старый. Сервер хранит список независимо от копии, возвращённой UI.

Перед сохранением повторно проверяются путь/поколение привязки, политика/головы/режимы, включённые файлы с их метаданными и перечень пропущенных объектов. Новая ревизия, смена привязки или изменение проверяемой части дерева требуют свежего просмотра. Содержимое исключённых поддеревьев не исследуется и не даёт разрешения на работу с ним.

Фиксация сериализована с подготовкой/применением через очередь сессии. Старый watcher останавливается, после результата создаётся новый с сохранёнными правилами. Смена правил увеличивает локальное поколение разрешения файловых операций, отменяет устаревшие предпросмотры восстановления/конфликтов и полномочия старых операций, сохраняя применённые отпечатки. Уже завершившаяся подписанная операция остаётся частью истории. Исключённые пути убираются из очереди публикации; прочие пути пересканируются. Ошибка записи настроек не разрешает работать по несохранённым правилам.

Проверенные торрент-метаданные незавершённой загрузки удерживаются в ограниченном кеше текущего сервиса: до 32 записей, без содержимого документов. При быстром снятии маски они используются повторно, чтобы не ждать сетевого ограничения частоты повторного ответа. Каждая запись проверена против подписанной ревизии; выдаётся отдельная копия байтов, кеш очищается при закрытии сервиса.

## Проверки

Тесты покрывают маски и Unicode, границы/неподдерживаемый синтаксис, служебные исключения, причины пропуска каталогов, миграцию и запись защищённого индекса, сброс при перепривязке, сохранение применённых отпечатков и фильтрацию очереди. Проверены устаревшие/повторные токены, срок, изменение файла/головы/привязки, постраничный вывод, исправление чрезмерного дерева, недоверенный IPC, прямой обход сервисного API и смена правил в процессе загрузки. Снятие маски получает актуальную голову; локальные правки остаются конфликтом.

`npm run test:room-sync-ui` проходит настоящий React/preload/IPC, DPAPI и E2E WebRTC. Через UI исключается `config.ini`, новое общее содержимое не заменяет рабочий файл. Получатель перезапускается, сохранённая маска проверяется, затем снимается через повторный предпросмотр. Последняя общая версия применяется, а последующая публикация после перезапуска издателя снова доставляется. Широкие и узкие снимки: `dist/room-sync-ui/evidence/filters-wide.png`, `filters-narrow.png`.

Утилита `room-sync:acceptance manifest` проверяет дерево с встроенными исключениями и не читает настройки профиля: пользовательские маски в такой независимой сверке автоматически не учитываются. Дополнительные исключённые файлы издателя могут появиться как ожидаемые различия. Проверка Office/IDE на двух физических ПК остаётся отдельной приёмкой.

Проверка этапа: общий прогон — 3388 тестов в 249 наборах; после дополнительных изменений прошли все 21 проверка координатора, включая чрезмерное дерево и возврат прерванной загрузки. Отдельно прошли восемь проверок Node, typecheck Electron/renderer/guest, сборки всех трёх частей и ESLint изменённых модулей. Полный нативный UI/E2E-сценарий прошёл; широкие и узкие снимки просмотрены. Сборка renderer сохраняет три предупреждения о размере bundle.

Окончательная сборка после добавления повторного использования проверенных метаданных прошла ещё один нативный прогон `--ui --conflicts-only`, включая исключения, перезапуск и получение последней головы после снятия маски.
