# Обновления интерфейса по видимости — OPT-03

Дата: 25 октября 2026 года.

## Поведение

В скрытом или свёрнутом главном окне модель загрузок сохраняет общую подписку
на IPC. Пауза, ошибка, завершение и смена доступных действий операции продолжают
публиковаться сразу. Обычные числа скорости, прогресса и числа пиров объединяются
в один последний снимок без таймера; пятиисекундный опрос метаданных останавливается.
Неизвестный движку интерфейса идентификатор обнаруживается с ограниченной частотой,
чтобы ожидание метаданных не превращало каждый пакет в срочную перерисовку.

При возвращении видимого потребителя последний снимок публикуется сразу,
затем запрашиваются свежие метаданные. Если запрос начался до возвращения,
его результат инвалидируется и выполняется повторный запрос. Актуальная push-статистика
сохраняет приоритет над более редко сохраняемым прогрессом из БД. Повторные владельцы
модели используют одну подписку; освобождение последнего владельца снимает её и таймеры.

В открытом окне без страницы загрузок и без строки состояния числовая статистика
тоже может отдыхать. Опрос метаданных остаётся для счётчиков боковой панели.
Плеер регистрирует собственную потребность в статистике источника через
`MediaBufferStatus`: его видимое вынесенное окно продолжает получать скорость и пиров,
даже если главное окно скрыто. Когда скрыты оба окна, эта потребность освобождается.

`VisibleWorkProvider` передаёт выбранную вкладку дока, парковку и скрытие центральной
зоны сценой. Он сохраняет структуру React и DOM живых панелей. Только читающие опросы
предпросмотра файлов, здоровья сервера, списка документов и рабочих папок учитывают
эту активность и видимость своего окна. Переход к видимой панели запускает свежий
запрос сразу. Следующий периодический запрос планируется после ответа, поэтому
медленный IPC не создаёт нарастающую очередь запросов. Ответы от уже скрытого опроса
не обновляют панель. Незавершённое открытие редактора по действию пользователя
сохраняет свой жизненный цикл и освобождение токена.

Вынесенные панели используют `HostWindowRealm` / `HostWindowProvider`, свой
`document.visibilityState` и таймеры своего окна. У медиакомпонента документ
элемента имеет приоритет над контекстом. Сворачивание главного окна не останавливает
видимую панель в дочернем окне; восстановление дочернего окна обновляет её независимо.

## Границы

Экономный режим OPT-01 по-прежнему задаёт интервал видимых чисел и предпросмотра.
Смена режима в скрытом окне не публикует отложенные числа сама по себе.
При наличии видимого плеера модель остаётся активной для его статистики.

Частота IPC движка, транспорт, heartbeat, сохранение документов, воспроизведение,
таймеры готовности совместного просмотра и предзагрузка не менялись. Фоновый пакет
всё ещё принимается и проверяется на критичные изменения. Оптимизация уменьшает
работу модели и React, но не обещает уменьшения трафика движка или расхода батареи.

Страницы Havvn уже размонтируются при уходе с маршрута; дополнительного кеширования
или второго механизма подписок для них не добавлено. У дока сохранены правила
keep-alive. Видимость отдельных строк при прокрутке не отслеживается.

## Проверки и измерения

Команды:

```powershell
npm run test:visibility
npm run test:visibility-ui
node scripts/performance-baseline.cjs --runs 3 --scenario downloads-1000 --sample-ms 6000 --stats-tick-ms 100 --visibility hidden --output artifacts/visibility-performance/new-run
```

UI-приёмка использует реальные компоненты App, дока и плеера, изолированный профиль,
локальный WAV-файл и синтетический API. Проверяются настоящее сворачивание/восстановление
окон Electron, сохранность медиэлемента и продолжающееся воспроизведение, отдельные
потребители статистики, скрытые вкладки, парковка и освобождение подписок.
В стенде отключено определение перекрытия окна другими приложениями, чтобы окно Codex
не меняло видимость посреди проверки; native minimize и background throttling сохранены.
Результат: `artifacts/visibility-ui/result.json` — 18 проверок без ошибок.

Численный стенд отдельно использует управляемый `visibilitychange` при отключённом
системном throttling. Это измерение политики приложения на синтетических данных,
а не имитация измеренного расхода батареи или скорости реального торрента.
У каждой серии сохраняются исходники в manifest, хеши bundle, три повтора и CDP-трассы.
Исходная серия снята до изменения рабочего кода; кандидат использует те же условия
и объём данных. Реальная видимость окон проверяется отдельной UI-приёмкой выше.

Исходные публикации React на 60 пакетах статистики: **65 / 62 / 62**, после изменения:
**1 / 1 / 1**. Первая публикация нужна для первичного снимка статистики; обычные
числа затем откладываются. Запросы `getDownloads` внутри измеряемого отрезка:
**2 / 1 / 1 → 0 / 0 / 0**. Это счётчики фактически выполненной работы на стенде.

Первый кандидат в `artifacts/visibility-performance/after` отклонён самим стендом:
в третьем повторе изменилась схема питания Windows. Повторная серия
`after-stable` завершилась на одной схеме, но она отличается от исходной `before`.
Поэтому сравнение CPU, времени, задержек и порогов не заявлено; схемы не подменялись
и системные настройки не менялись. Для будущего `--compare` нужна одинаковая схема
в обеих сериях. Все сырые данные и причина отказа сохранены, итог счётчиков —
`artifacts/visibility-performance/comparison.json`.
