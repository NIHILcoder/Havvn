# FUN-03. Возможности движков и исследование предзагрузки Native

Дата проверки: 26 октября 2026 года. Havvn 3.2.0, Windows, один физический ПК.

FUN-03 завершён в части общего контракта, интерфейса и технического прототипа. Ограниченная предзагрузка в Native **не выпущена**: прототип не подтвердил необходимую независимую выборку с ограничением объёма. Это предусмотренная планом ветка с сохранением ограничения. Результат не означает завершение FUN-01 или общей релизной приёмки.

## Контракт возможностей

`shared/engine-capabilities.ts` определяет ответ версии 1 и четыре признака поддержки реализации:

- `boundedEpisodePrefetch` — ограниченная предзагрузка следующей серии: Classic поддерживает, Native не поддерживает.
- `autoMoveCompleted` — перенос завершённых загрузок: Classic поддерживает, Native не поддерживает.
- `dnsOverHttps` — DNS-over-HTTPS движка: Classic поддерживает, Native не поддерживает.
- `vpnInterfaceBinding` — привязка движка к VPN-интерфейсу: Native поддерживает, Classic не поддерживает.

Поддержка означает наличие реализации в Havvn. Она не подтверждает исправность запущенного движка, включение настройки, доступность VPN, отсутствие утечек или измеренный маршрут соединения.

`downloads:engineCapabilities` доступен через production preload. Прокси получает движок из кешированного `getHostEnv()` — того же окружения, которое передаётся в torrent host. Учитываются переменная `HAVVN_ENGINE` и переход на Classic при отсутствии Native binary. Чтение возможностей не запускает utility process или daemon и не записывает настройки. Изменённый в настройках выбор применяется после перезапуска и до этого не меняет отчёт текущего запуска. Старый `app:getRunningEngine` использует тот же источник. Legacy `getEpisodePrefetchSupport` сохранён, ответы обоих менеджеров согласованы с новым контрактом.

Renderer проверяет версию, название движка, полный набор признаков, типы и причины. Неизвестный или повреждённый ответ не включает функции. При загрузке и ошибке запроса показаны разные состояния; лишние поля ответа не переносятся в модель интерфейса.

## Что изменилось в интерфейсе

В общей карточке выбора движка появился список возможностей **этого запуска**. Причины недоступности переведены на русский и английский. Ожидающий перезапуска выбор движка не выдаётся за активную поддержку.

Перенос завершённых загрузок, DoH и привязка к интерфейсу используют явные признаки поддержки. До получения ответа недоступные действия выключены. Сохранённые предпочтения сохраняются при смене движка; недоступная настройка не изображается включённой.

В проигрывателе Native показывает причину ограничения и предложение использовать Classic после перезапуска. Неработающих настроек включения, бюджета и согласия для исключённого файла нет. Загрузка или ошибка запроса возможностей также не запускает предзагрузку. Настройки Classic, в том числе включение и бюджет, переживают открытие проигрывателя в Native. В списках Select отметка выбранного варианта заменена на выровненный CSS-кружок без символа галочки; `aria-selected` сохранён.

## Прототип Native

Воспроизводимый сценарий: `npm run probe:native-prefetch`. Использован входящий в проект Transmission **4.1.3 (838877323f)**; SHA-256 binary: `397dd842bbb4398f0e35a5b299af19add28d8175564017b6f239a855646665bd`.

Исследование запускало отдельный daemon с временными config/download/profile, случайными RPC/peer-портами и HTTP web seed на loopback. DHT, PEX, LPD и port forwarding выключены. Данные пользователя и работающий dev-процесс не использовались. После остановки daemon временная директория удаляется с проверкой её расположения.

Два случайных файла по 4 МиБ разбиты на куски по 256 КиБ. Для текущего файла установлен высокий приоритет, для следующего — низкий. Условный требуемый бюджет головы следующего файла: 1 МиБ.

1. Пока следующий файл исключён, текущий скачивается полностью, следующий остаётся на 0 байт.
2. Первая попытка только с `files-wanted` не дала передачи следующего файла за 30 секунд. Её неуспешный отчёт сохранён отдельно: `artifacts/fun03/native-probe-initial.json`, лог `artifacts/fun03-native-probe-initial.log`.
3. В повторном прототипе добавлен сдвиг общего `sequential_download_from_piece` на начало следующего файла. Следующий файл скачался на **4 194 304 байта** при требуемом бюджете **1 048 576 байт**. Низкий приоритет остался низким; сам по себе он не ограничил объём.
4. Исключение следующего файла возвращается через `files-unwanted`. Общий курсор принимает значения 0 → 16 → 0; отдельной независимой выборки для предзагрузки этот интерфейс не предоставляет.

Четыре проверки исследовательского сценария прошли. `passed: true` в `artifacts/fun03/native-probe.json` означает, что эксперимент воспроизвёл ограничение; поле **`releaseNativePrefetch: false`** явно запрещает трактовать его как приёмку Native-предзагрузки. Отмена выбора проверена после передачи файла и не доказывает жёсткую остановку на бюджете в полёте. Прототип не измерял одновременное качество просмотра и не доказал отсутствие влияния на текущее видео.

Официальные источники проверены для той же версии: [RPC Transmission 4.1.3](https://github.com/transmission/transmission/blob/4.1.3/docs/rpc-spec.md), [реализация RPC](https://github.com/transmission/transmission/blob/4.1.3/libtransmission/rpcimpl.cc). Доступны выбор целых файлов, приоритеты и общий последовательный курсор. Контракта независимого диапазона кусков с собственным бюджетом и временем жизни в этом API нет. Поэтому опрос счётчиков с последующим исключением файла не включён как обходной путь: передача может перескочить бюджет между измерениями и затронуть текущую последовательную загрузку.

Для будущей реализации Native нужна отдельная работа над возможностями daemon/API и новой приёмкой объёма, отмены и приоритета текущего видео. При текущем контракте функция остаётся недоступной.

## Проверенная предзагрузка Classic

Существующая реализация Classic использует независимую выборку диапазона: текущий поток имеет более высокий приоритет; сохранённые приоритеты файлов не меняются. Бюджет округляется до границ кусков и ограничивает дополнительную выборку, а не всю загрузку выбранного файла. Он не обещает конкретное число секунд видео или общий предел сетевого трафика торрент-клиента.

Запуск допускается в конце серии при непрерывном буфере текущего видео не менее 20 секунд. Пауза, перемотка, ожидание потока, ошибка, нехватка буфера, смена файла, закрытие проигрывателя и экономный режим снимают дополнительную выборку. Непродлённая аренда истекает через 5 секунд. Для исключённого файла требуется согласие. Пауза загрузки не снимается автоматически.

Отдельный тест реальных локальных пиров скачал ровно 1 МиБ головы следующего файла при бюджете 1 МиБ и сохранил выборку текущего файла. Это локальная проверка передачи, не измерение качества просмотра на внешней сети.

## Проверки и воспроизведение

- `npm run test:engine-features` — 84 теста в 7 файлах: матрица и проверка ответа, оба менеджера, прокси, ожидающий перезапуска выбор, fallback, аренды/бюджет/условия и монтаж настроек.
- `npx vitest run electron/torrent/episode-prefetch-loopback.test.ts` — 1 тест реальной передачи Classic.
- `npm run test:engine-features-ui` — отдельный Electron с реальным WebM, управляемыми паузой/перемоткой/буфером, настройками бюджета и согласия; Native без неработающих контролов; возврат предпочтений Classic; загрузка/ошибка возможностей; четыре признака обоих движков и ширины 400/1000. Временный профиль, 13 групп проверок. Отчёт и снимки: `artifacts/fun03/ui/`.
- `node scripts/smoke-resource-mode.cjs` — экономный режим останавливает предзагрузку, сохраняет предпочтения и просмотр; выход учитывает новый отказ пользователя. Проверено сохранение режима в новом Electron-процессе.
- `npm run typecheck` и `npm run build` прошли. Production webpack сохранил три предупреждения о размере bundle/entrypoint.
- Линтер нового кода FUN-03 прошёл без замечаний. Расширенный запуск по крупным затронутым файлам не чистый: прежние CommonJS `require` в менеджерах и предупреждения `any`/unused остаются; он не считается успешным общим lint проекта.

Каноническая запись локальной приёмки с хешами исходников и доказательств: [engine-capabilities-acceptance.json](engine-capabilities-acceptance.json). Логи — `artifacts/fun03-*.log`. Проверки на Linux/macOS, двух физических ПК, внешних пирах и новый пакет установщика в этой задаче не выполнялись. FUN-01 и аппаратные/сетевые части OPT-02 остаются открытыми, а после дальнейших изменений сборки требуют повторной релизной приёмки.
